## 1. 암호학

> 암호학 & 인증(PKI·전자서명) · 자세한 풀이는 `1암호학.md`를 봐.

### 🔥 이것만은 꼭

- 공격 강도: **암호문 단독 < 기지평문 < 선택평문 < 선택암호문**
- **워터링홀** = DRM 기술 ❌ (자주 가는 사이트를 감염시키는 공격 기법)
- **대칭키** AES · SEED · ARIA · IDEA / **비대칭키** RSA · ECC · Rabin
- **OTP** = 평문만큼 긴 랜덤키를 1회만 사용 → **완전 비밀성**. "전수공격하면 결국 해독된다"는 ❌ (모든 평문 후보가 나와서 정답을 구별 못 함)
- **해시값에 서명**하는 이유 = 공개키 연산이 느려서 **속도** 때문
- **Kerberos**는 전자서명 적용 예 ❌ (대칭키·KDC 기반) ↔ Code Signing · X.509 · SSL/TLS는 ⭕
- **복호형(메시지 복원형) 전자서명** = 일반서명 분류 ↔ 부인방지 · 의뢰부인방지 · 수신자지정 = 특수목적 서명
- **신원확인 = RA, 발급·서명 = CA**

### 📊 한눈에 비교

#### DRM · 콘텐츠 보호
| 용어 | 한 줄 정리 |
|---|---|
| 워터마킹 | **저작권자** 정보를 안 보이게 삽입 |
| 핑거프린팅 | **구매자** 정보 삽입 → 유출자 추적 |
| 스테가노그래피 | 정보가 있다는 **사실 자체를 숨김** |
| 메타데이터 | 저작권자·이용규칙 등 **정보 그 자체** |
| 패키저 | 콘텐츠+메타데이터를 암호화해 **포장하는 도구** |
| 시큐어 컨테이너 | 포장 결과물 = **안전한 상자** |
| DRM 제어기 | 이용 권한(횟수·기간)을 **통제하는 문지기** |
| 클리어링 하우스 | 라이선스(키) 발급 · 저작권료 **정산** |

(스마트태그 = RFID 등 식별 태그 · VOD DRM = 주문형 비디오 보호 · 보안토큰 = 키 저장 하드웨어)

#### 암호 설계 · 분석
| 용어 | 한 줄 정리 |
|---|---|
| 혼돈 | 키와 암호문의 관계를 숨김 (치환 · S-Box) |
| 확산 | 평문 특성을 암호문 전체로 퍼뜨림 (전치 · 눈사태 효과) |
| 차분공격 | 평문 쌍의 **차이(XOR)** 분석 |
| 선형공격 | **선형 근사식** 분석 |
| 전수공격 | 모든 키를 대입 |
| 통계적 분석 | **문자 빈도** 분석 (고전암호에 강함) |

#### 대칭키 알고리즘
| 알고리즘 | 특징 |
|---|---|
| AES | 미국 NIST · 128비트 블록 · 키 128/192/256 · SPN |
| SEED | 한국 KISA · 128비트 · Feistel |
| ARIA | 한국(국가기관·학계) · SPN · 경량환경 |
| IDEA | 스위스 · PGP에서 사용 |

#### 블록암호 운용모드
| 모드 | 수식 | 특징 |
|---|---|---|
| ECB | `C_i = E_K(P_i)` | 블록 독립 → **패턴 노출**, 병렬 가능 |
| CBC | `C_i = E_K(P_i XOR C_(i-1))`, `C_0 = IV` | 도미노, 가장 널리 사용 |
| CFB | `C_i = P_i XOR E_K(C_(i-1))` | 스트림처럼 동작 |
| OFB | `O_i = E_K(O_(i-1))`, `C_i = P_i XOR O_i` | 오류 전파 없음 |
| CTR | `C_i = P_i XOR E_K(Counter_i)` | 병렬 · 랜덤 접근 |

#### 키 분배 · RSA
| 항목 | 한 줄 정리 |
|---|---|
| KDC | 신뢰기관이 세션키를 배분 (Kerberos) |
| Diffie-Hellman | 공개 채널로 공통키 생성 · **이산대수** 문제 기반 · 키 교환만 · 인증 없음 → 중간자 공격 취약 |
| RSA 키분배 | 세션키를 **상대 공개키**로 암호화해서 전송 (하이브리드) |
| RSA 안전성 | p·q 큰 소수 · 너무 가깝지 않게(페르마) · p-1·q-1에 큰 소인수(폴라드 p-1) · gcd(e, φ(n)) = 1 |

#### 해시 · MAC
| 항목 | 한 줄 정리 |
|---|---|
| 강한 충돌내성 | **아무** 두 입력 x, x'에서 H(x)=H(x')를 찾기 어려움 |
| 약한 충돌내성 | **주어진** x에 대해 같은 해시의 x'를 찾기 어려움 (제2원상저항성) |
| MDC | **키 없음** — MD5 · SHA 계열, 무결성 |
| MAC | **비밀키 있음** — HMAC, 무결성 + 인증 |

#### 전자서명
- 요구조건: **위조불가 · 서명자인증 · 부인불가 · 재사용불가** (+ 변경불가)
- 서명 = **개인키**로 암호화 → 검증 = **공개키**

| 알고리즘 | 기반 · 특징 |
|---|---|
| RSA 서명 | 소인수분해 |
| Schnorr | 이산대수 · 간단하고 효율적 |
| DSS | NIST 표준 · DSA(이산대수) · **서명 전용** |
| ECDSA | 타원곡선 이산대수 · 짧은 키로 같은 안전성 |

#### 전자투표 · 전자입찰
| 구분 | 핵심 |
|---|---|
| 전자투표 요건 | 완전성 · 익명성 · 건전성 · 이중투표방지 · 정당성(적임성) · 검증가능성 |
| 투표 방식 | **PSEV** 지정 투표소 → **Kiosk** 공공장소 키오스크 → **REV** 원격(PC·스마트폰) |
| 전자입찰 | 공정성 · 안전성(개찰 전 비공개) · 익명성 · 부인방지 |

#### PKI · 인증서
| 기관 | 역할 |
|---|---|
| PAA | 최상위 정책 승인 |
| PCA | 정책 인증, 하위 CA 관리 |
| **CA** | 인증서 **발급·서명** |
| **RA** / LRA | **신원확인** 대행 / 지역 RA |
| VA | 인증서 유효성 검증 |

- X.509: 버전 · 일련번호 · 서명알고리즘 · 발급자 · 유효기간 · 주체 · 공개키 · 확장 · **CA 서명**
- **CRL** = 폐지 인증서 목록(주기적 배포, 실시간성 낮음) ↔ **OCSP** = 서버에 실시간 조회
- SSO = 한 번 로그인으로 여러 시스템 이용 · HSM = 암호키 보관 전용 하드웨어

## 2. 접근통제

> 접근통제(Access Control) · 자세한 풀이는 `2접근통제.md`를 봐.

### 🔥 이것만은 꼭

- **식별 → 인증 → 인가** = 아이디 입력 → 진짜인지 확인(비번·OTP·지문) → **권한 부여**
- **최소 권한** = 딱 필요한 만큼만. 권한 이양·제거·양립은 보기용 함정이고 답은 거의 최소 권한
- ⚠️ **No Read Down / No Write Up**이 나오면 "상업용"이 같이 나와도 **Biba** (Clark-Wilson ❌)
- **MAC 대표 모델 2개** = **BLP(비밀성)** · **Biba(무결성)**

### 📊 한눈에 비교

#### 접근통제 3방식
| 방식 | 권한 설정 | 키워드 |
|---|---|---|
| **DAC** | 사용자(소유자)가 마음대로 | ACL · Capability List |
| **MAC** | **관리자만** | 보안등급(Label) · BLP · Biba · 군대·정부 |
| **RBAC** | **역할(Role)**에 부여 | 최소권한 · 직무분리 · 데이터 추상화 |

#### 정책 · 메커니즘 · 보안모델 · OSI 보안구조
| 용어 | 한 줄 정리 |
|---|---|
| 정책 | 누가 무엇을 할 수 있는지 정한 **규칙** |
| 메커니즘 | 규칙을 실제로 지키게 하는 **기술** |
| 보안모델 | 보안정책을 표현한 **설계도** (BLP · Biba · Clark-Wilson) |
| OSI 보안구조 | **보안서비스 · 보안메커니즘**을 정의한 국제표준(X.800) |

#### 보안모델 4개
| 모델 | 목적 | 키워드 |
|---|---|---|
| **BLP** | 비밀성 | **No Read Up / No Write Down** (기밀이 아래로 새는 걸 막음) |
| **Biba** | 무결성 | **No Read Down / No Write Up** · 상태머신 · 등급(Label) 기반 |
| **Clark-Wilson** | 상업용 무결성 | 트랜잭션 · 승인절차 · 직무분리 (은행·기업) |
| **Chinese Wall** | 이해충돌 방지 | 경쟁사 동시 접근 금지 · DAC + MAC 혼합 |

> 🔑 키워드 반사: 비밀성 → BLP / 무결성(등급 규칙) → Biba / 상업용·트랜잭션 → Clark-Wilson / 이해충돌 → Chinese Wall

### ❌ 오답 한 줄 요약

| 문제 | 정답 |
|---|---|
| MAC의 특징이 아닌 것 | ACL · Capability List (DAC 구현 방식) |
| RBAC의 특징이 아닌 것 | 다단계 보안등급 (MAC 특징) |
| 접근통제 매트릭스(ACM) | 사용자×자원 표 → 커지면 관리 어려움 → ACL(열) / Capability(행)으로 쪼갬 |
| 보안모델 (No Read Down / No Write Up) | **Biba** (Clark-Wilson 아님) |
| BLP의 특징 | 비밀성만 보호, 무결성 ❌ |
| 만리장성 모델 | 핵심은 **이해충돌 방지** |

## 3. 시스템보안

> 시스템 보안 (해킹과 보안) · 자세한 풀이는 `3시스템보안.md`를 봐.

### 🔥 이것만은 꼭

- **트로이목마** = 위장(자기복제 ❌) ↔ **웜** = 자기복제 / **백도어** = 몰래 들어오는 문 ↔ **스파이웨어** = 몰래 정보 수집
- **400** = Bad Request, **404** = Not Found
- **NTFS 권한**은 로컬 + **네트워크 접근**에도 적용 / **SID 마지막 숫자 = RID** (500 Administrator · 501 Guest) / **SAM**은 Administrator·System만
- **umask 022** → 디렉터리 **755** · 파일 **644**
- **Sticky Bit = `t`** (s ❌) · **대문자 `S`** = SetUID/GID는 있지만 실행권한(x) 없음
- **shadow**는 암호화 ❌ **해시** ⭕
- ⚠️ **utmp = 현재** 로그인 / **wtmp = 이력** (`last`는 wtmp)
- ⚠️ **EXT** inode 테이블: 교재 기준 **파일시스템**당 1개 (실제 구현은 블록 그룹마다)
- **ASLR** = 주소 랜덤 · **DEP/NX** = 실행 금지 · **Canary** = 덮어쓰기 감시
- **다크웹 ⊂ 딥웹** (다크웹이 딥웹의 일부)

### 📊 한눈에 비교

#### 악성코드 · HTTP · IE
| 용어 | 한 줄 정리 |
|---|---|
| 트로이목마 | 정상 프로그램으로 **위장**, 자기복제 ❌ |
| 웜 | 혼자 네트워크로 **자기복제** |
| 바이러스 | 사람 도움(USB·첨부파일 실행 등)이 있어야 퍼짐 |
| 백도어 | 공격자가 몰래 들어오는 **비밀 출입구** |
| 스파이웨어 | 동의 없이 설치돼 **개인정보 수집** |
| 논리폭탄 | 특정 조건이 맞을 때 동작 |
| autorun.inf | USB를 꽂으면 프로그램을 자동 실행시키는 파일 |

- HTTP 요청 순서: **Request Line → Header → Blank Line → Body**
- 상태코드: 200 OK · 301 영구이동 · 302 임시이동 · 304 캐시 사용 · **400 Bad Request** · 401 Unauthorized · 403 Forbidden · **404 Not Found** · 408 Timeout · 500 서버오류 · 503 서비스 불가
- IE 보안영역 4개: **인터넷 · 로컬 인트라넷 · 신뢰할 수 있는 사이트 · 제한된 사이트** (인로신제)

#### Windows
| 항목 | 한 줄 정리 |
|---|---|
| NTFS | 파일 권한 · 암호화(EFS) · 감사 / 최대 16EB / 권한은 **로컬+네트워크** 모두 적용 |
| SID | `S-버전-권한-컴퓨터ID-RID` / **RID 500 = Administrator, 501 = Guest** |
| SAM | 계정·패스워드(해시) 저장 / **Administrator · System**만 접근 |
| 레지스트리 | **HKCU** 현재 사용자 1명 · **HKLM** 컴퓨터 전체 · **HKCR** 파일 연결 · **HKCC** 현재 하드웨어 · HKEY_USERS 전체 사용자 |
| 원격제어 도구 | NetBus · pcAnywhere · VNC ⭕ / **BackOffice** ❌ (MS 서버 제품군) |
| 서버 보안 설정 | "원격 시스템에서 강제 종료" 권한은 **Administrators만** (전 계정 등록 ❌) |

#### Unix/Linux 명령 · 권한
| 항목 | 한 줄 정리 |
|---|---|
| 좀비 프로세스 | `ps`에서 STAT = **Z** → `kill` |
| Device is busy | **`lsof`** (열린 파일 목록) |
| 소유자·그룹 없는 파일 | `find -nouser` / `-nogroup` (`find / -ls`는 ❌) |
| 종합 모니터링 | **`top`** (CPU · 메모리 · 부하율) |
| 프로세스 트리 | **`pstree`** |
| TCP Wrapper | `/etc/inetd.conf` |
| 암호 파일 | `/etc/shadow` — **해시** 저장 · 필드 순서: 마지막변경일 → 최소 → **최대** → 경고 |
| 특수권한 표기 | SetUID · SetGID = `s` / Sticky = `t` / 대문자 `S` = 실행권한(x) 없음 |
| umask 022 | 디렉터리 **755** · 파일 **644** (777·666에서 022를 뺌) |
| ⚠️ EXT 파일시스템 | Super Block = 파일시스템 기본 정보 · inode 테이블은 교재 기준 **파일시스템**당 1개 |

#### 로그
| 항목 | 한 줄 정리 |
|---|---|
| Windows 이벤트 로그 | `.evt`(XP 이전) / `.evtx`(Vista 이후) · **이벤트 뷰어**로 확인(메모장 ❌) · 크기 변경 가능 · 보안 로그 = 로그인·접근 기록 |
| **utmp** | **현재** 로그인 사용자 (`who`) |
| **wtmp** | 로그인·로그아웃 **이력** (`last`) |
| btmp | 로그인 **실패** (교재에선 "5회 이상 실패"로 출제돼도 맞는 설명으로 취급) |

## 4. 네트워크보안

> 네트워크 보안 · 자세한 풀이는 `4네트워크보안.md`를 봐.

### 🔥 이것만은 꼭

- **MAC 주소** = 48비트 = 16진수 **6묶음** / 압축·암호화 = **표현 계층**(데이터링크 ❌) / Flag · Bit Stuffing = **데이터링크 계층**
- **CSMA/CD** = 충돌 **탐지**(유선) ↔ **CSMA/CA** = 충돌 **회피**(무선)
- **/27 = 255.255.255.224** · **Socket = IP + Port**(MAC ❌) · **Anycast** = 가장 가까운 **한 명**
- **PAT** = 공인 IP 1개 + **출발지 포트**로 구분 (Well-known Port 변환 ❌)
- **Slow Start**는 이름과 달리 임계치까지 **2배씩** 증가 → 이후 혼잡회피(1씩)
- **다익스트라 = 링크상태(OSPF)** ↔ 거리벡터 = RIP
- ⚠️ **NIC** = 병렬 → **직렬** 변환 ("병렬구조로 바꾼다"는 ❌)
- ⚠️ **DDoS 도구** = Trinoo · TFN · TFN2K · Stacheldraht (Smurf는 도구가 아니라 기법)
- ⚠️ **방화벽 ACL** = 위에서부터 검사, **먼저 걸린 규칙**만 적용
- **OAuth**(RFC 5849) = 권한 위임 ≠ **OIDC** = 사용자 인증

### 📊 한눈에 비교

#### IP · ICMP · NAT
| ICMP 메시지 | 의미 |
|---|---|
| **Source Quench** | 혼잡 → "너무 많이 보내지 마" |
| Destination Unreachable | 목적지 못 감 |
| Time Exceeded | TTL 끝 (traceroute) |
| Parameter Problem | 헤더 오류 |

- 서브넷 마스크(255.255.255.x): `/24`=0 · `/25`=128 · `/26`=192 · **`/27`=224** · `/28`=240
- 전송 방식: Unicast(한 명) · Broadcast(전원) · Multicast(그룹) · **Anycast(가장 가까운 한 명)** — "일부 수신자"라는 표현은 ❌

| NAT | 특징 |
|---|---|
| Static | 1:1 고정 (IP 절약 ❌) |
| Dynamic | 공인 IP 풀에서 빌림 (다 배정되면 인터넷 연결 제한) |
| **PAT** | 공인 IP 1개 + 포트 번호로 여러 대 구분 |

- NAT는 보안기술 자체는 아니지만 사설 IP를 숨기는 **부수 효과**는 있음 ("전혀 없다"는 ❌)

#### 라우팅
| 구분 | 방식 | 대표 |
|---|---|---|
| 거리벡터 | 옆 라우터에게 길을 물어봄 | RIP |
| 링크상태 | 전체 지도를 만들고 다익스트라로 계산 | **OSPF** |

- 텔넷 로그인 설정: `username`(전역설정모드) → `line vty 0 4` → `login local`
- **Default Route** = 목적지 정보가 없을 때 보내는 "기본 길"
- 라우터 보안: **Egress** = 나가는 패킷 검사 · **Ingress** = 들어오는 패킷 검사 · **Blackhole** = 특정 트래픽 폐기 · **uRPF** = 라우팅 테이블로 출발지 IP 확인(위조 탐지) → "인터페이스 확인" 설명은 Blackhole ❌, uRPF ⭕

#### NIC · VLAN
- NIC: 네트워크 연결 · 버퍼 저장 · **병렬↔직렬 변환** (압축 ❌ = 표현 계층)

| VLAN 종류 | 기준 |
|---|---|
| 포트 기반 | 스위치 포트 |
| MAC 기반 | MAC 주소 |
| **프로토콜 기반** | IPv4 · IPv6 · IPX 같은 **프로토콜 종류** |
| IP 서브넷 기반 | IP 주소 대역(네트워크 주소) |

#### 무선 · 인증
| 항목 | 한 줄 정리 |
|---|---|
| 장비 인증 | **MAC 주소** 기반 ("누구"가 아니라 "어떤 장비") |
| 순방향 기밀성 | 현재 세션키·마스터키가 털려도 **과거 트래픽은 안전** |
| Android 보안 | 민감정보를 SD카드 등 **외부 저장소**에 두면 ❌ (TLS · 명시적 Intent · 로그에 민감정보 금지는 ⭕) |
| 인증 프로토콜 | RADIUS · Kerberos · TACACS ⭕ / **PGP** ❌ (메일 암호화·전자서명) |

#### 네트워크 명령어
| 명령어 | 역할 |
|---|---|
| ifconfig | NIC 정보 (DNS와 무관) |
| ping | **ICMP**로 연결 확인 (IDP ❌) |
| traceroute | 목적지까지 **경로** (내 컴퓨터 내부 상태 ❌) |
| nslookup · dig | DNS 조회 (bind = DNS 서버 프로그램) |
| tcpdump | 패킷 캡처 · 분석 |

#### 공격 (DoS · DDoS · 스캔 · 하이재킹)
| 공격 | 핵심 키워드 |
|---|---|
| **Smurf** | ICMP + 브로드캐스트 + IP Spoofing |
| Ping of Death | 비정상적으로 큰 ICMP |
| **SYN Flood** | TCP SYN 대량 → Half Open (Teardrop과 무관) |
| UDP Flood | UDP 대량 / 없는 포트 → **ICMP Unreachable** |
| Teardrop | Fragmentation + 비정상 offset |
| Tiny Fragment | Fragment를 아주 **작게** 쪼갬 |
| Fragment Overlap | Fragment가 **겹쳐서** 덮어씀 |
| LAND | 출발지 IP = 목적지 IP |
| Session Hijacking | **이미 만들어진 세션** 탈취 (ACK Storm · 비동기화로 탐지) |
| DNS Spoofing | **가짜 DNS 응답** (세션 하이재킹 ❌) |

- DoS 특징: 루트 권한 획득 ❌ · 데이터 변조·탈취 ❌ · **가용성** 공격 · 방법 다양 · 추적은 **어려움**
- 정찰(Ping Sweep · Traceroute · DNS 정보)은 공격 전 단계 / **Smurf는 정찰이 아니라 공격**
- TCP **Half Open 스캔** = SYN → SYN+ACK → RST
- ICMP 이용 DoS = Smurf · Ping of Death (SYN Flood = TCP, UDP Flood = UDP)

#### IDS · EDR
| 항목 | 한 줄 정리 |
|---|---|
| H-IDS | 컴퓨터 **내부** 감시 → 트로이목마 설치 탐지에 유리 |
| N-IDS | **네트워크** 감시 → DDoS · 스캐닝 · SYN Flood에 유리 |
| 지식기반 탐지 | 시그니처 분석 · 페트리넷 · 상태전이 분석 |
| 행위(이상)기반 탐지 | **통계적 분석** |
| EDR | 탐지 · 통제 · 치료 (보안사고 **확산** ❌) |
| 금융 데이터 통제 | **비정상 데이터 유입의 통제** (예외처리) |

#### 방화벽 · VPN · NAC
| 항목 | 한 줄 정리 |
|---|---|
| 침입차단시스템 | 모든 트래픽 통과 · 허가된 것만 · 로그 추적 / RPC·SNMP 같은 관리 서비스 제공은 필수 ❌ |
| N-IPS | IP·포트 차단은 쉬움 / **악성코드 파일**은 payload 분석이라 어려움 |
| DPI | **payload**까지 검사 (애플리케이션 식별 · 트래픽 관리 · 유해 콘텐츠 차단) |
| VPN 계층 | PPTP · L2F = 2계층 / IPsec = 3계층 / **MPLS = 2+3계층** |
| L2TP | 2계층 터널, 보안은 **IPsec(IKE · ESP)**과 결합 |
| SSTP | SSL/TLS 기반 (TCP 443) |
| NAC | 단말 보안상태 점검 후 접근 허용·차단 ("안전하면 들어와") |
| NMS / ESM / UTM | 장비 관리 / 보안장비 로그 통합관제 / 여러 보안기능 통합 장비 |

## 5. 애플리케이션보안

> 애플리케이션 보안 (FTP·이메일·웹·DNS·DB·SET·포렌식) · 자세한 풀이는 `5애플리케이션보안.md`를 봐.

### 🔥 이것만은 꼭

- **FTP**: 기본 **Active**, 모드 선택은 **클라이언트** / 제어 **TCP 21** · Passive 데이터 **1024 이상**
- ⚠️ **PGP 표준 기능 5개** = 전자서명(인증) · 기밀성 · 압축 · 이메일 호환성 · **단편화/재조립** → "송신자 부인방지"는 기능 목록 ❌
- **PGP 기밀성** = 세션키(대칭키)로 메일 암호화 + **수신자 공개키**로 세션키 암호화 ("비밀키 미리 교환" ❌)
- **SSL/TLS** = 응용계층과 **TCP 사이** (네트워크·IP 계층 ❌ → 그건 IPsec)
- **Handshake** = 협상 · 인증 · 키 생성 / **Record** = 실제 데이터 캡슐화 · 암호화
- ⚠️ **Handshake 순서** = **4 → 5 → 1 → 2 → 3 → 6** (클라이언트 완료 → 서버 완료)
- **공개 웹서버** → **DMZ** (내부망 깊숙이 ❌)
- **WAF** = HTTP·웹 공격 ↔ 일반 방화벽 = IP/Port
- **Aggregation(집합)** = 조각을 모아 전체를 알아냄 ↔ **Inference(추론)** = 분석해서 유추
- **전자봉투** = 비밀키 + **수신자(B) 공개키**

### 📊 한눈에 비교

#### FTP
| 항목 | 한 줄 정리 |
|---|---|
| Active | **서버**가 클라이언트로 데이터 연결 (기본값) |
| Passive | **클라이언트**가 서버로 연결 (방화벽·NAT에 유리) |
| Anonymous FTP Attack | 익명 접속 + **쓰기 권한** → 악성코드 업로드 |

| 명령어 | 의미 |
|---|---|
| **STOR** | 파일 저장(업로드) |
| RETR | 다운로드 |
| RMD · MKD | 디렉터리 삭제 · 생성 |
| CWD · LIST | 디렉터리 이동 · 목록 |

#### 이메일 보안
| 항목 | 한 줄 정리 |
|---|---|
| S/MIME | 이메일 보안(공개키 · RSA · IETF RFC 3851) / **IEEE 802**(LAN·Wi-Fi 표준)는 무관 |
| Active Contents 공격 | HTML(+JavaScript·ActiveX) 실행을 악용 → **클라이언트** 공격 |
| 메일 서버 공격 | **DoS** (Active Contents · 트로이목마 · 바이러스 메일은 클라이언트 공격) |
| 발신자 IP 추적 | **Received** 헤더 (Return-Path = 반송주소 · Message-ID = 고유 ID · Reply-To = 회신주소) |

#### SSL/TLS
| 항목 | 한 줄 정리 |
|---|---|
| 구성 | Handshake · Change Cipher Spec · Alert · Record |
| 위치 | 응용 ↔ **TCP 사이** (IP 계층 보안 = IPsec) |
| TLS | SSL 3.0을 기반으로 만든 후속 (엄밀히 "동일"은 아님) |

| 순서 | Handshake 내용 |
|---|---|
| ④ | 클라이언트: SSL 버전 · 암호 설정 · 랜덤 데이터 전송 |
| ⑤ | 서버: 버전 · 암호 설정 · 랜덤 데이터 + **서버 인증서** |
| ① | 클라이언트: **Premaster Secret**을 서버 공개키로 암호화해 전송 |
| ② | 서버: Master Secret · 세션키 생성 |
| ③ | **클라이언트** 암호통신 준비 완료 알림 |
| ⑥ | **서버** 암호통신 준비 완료 알림 |

#### 웹 보안
| 항목 | 한 줄 정리 |
|---|---|
| 웹서버 보안 | 불필요 서비스 최소화 · 응용프로그램 권한 최소 · 로그 모니터링 ⭕ / **내부망에 배치** ❌ |
| Apache 디렉터리 리스팅 | `Options`에서 **`Indexes`** 삭제 |
| XSS 공격 절차 | **b → a → e → d → c** (심는다 → 본다 → 서버가 전달 → 브라우저 실행 → 결과 전송) |
| WAF | HTTP 공격 탐지 · 파일 업로드 검사 · 정보 유출 차단 / IP·Port 기반 차단은 일반 방화벽 역할 |
| CVE | 공개된 보안 취약점 **식별번호** (STIX = 위협정보 공유 · OWASP = 웹보안 프로젝트) |
| 운영체제 명령 실행 | `\|` `&` `;` `` ` `` 같은 특수문자 필터링 필요 |
| 정보 누출 | 에러·설정·DB·개인정보 노출 → 2차 공격에 악용 |

#### DNS
- 대표 취약점 = **Query 정보 변조 · Cache 변조(포이즈닝) · 서비스 거부(DoS)** / **중계 취약점** ❌

#### 데이터베이스 보안
| 항목 | 한 줄 정리 |
|---|---|
| 키 | 후보키(Candidate) 중 선택 → **기본키(Primary)** / 선택 안 된 나머지 → **대체키(Alternate)** / 외래키(Foreign) = 다른 테이블 참조 |
| **Aggregation(집합)** | 구성요소에는 접근 권한이 있지만 그걸 **모으면** 전체 정보를 알아냄 |
| Inference(추론) | 공개된 정보를 **분석**해서 숨겨진 정보를 유추 |
| 정보 흐름 통제 | 높은 보호수준 → **낮은 보호수준**으로 정보가 이동하는지 검사 (Aggregation 방지와 성격이 다름) |
| DB 보안 정책 | 최고경영자 승인 · 전 직원 접근 가능 · 교육·홍보 · 정기/비정기 검토·갱신 → **전부 맞음** |

#### 전자상거래(SET) · 포렌식
| 항목 | 한 줄 정리 |
|---|---|
| 전자봉투 | 데이터는 **비밀키**로 암호화 + 그 비밀키는 **수신자 공개키**로 암호화 |
| 포렌식 절차 | 수사 준비 → **증거물 획득** → 분석·조사 → 보고서 작성 |
| 증거물 획득 | 시스템 정보 기록 · 원본 사진 촬영 · 증거 라벨 부착 (원본 보존) |

## 6. 정보보호관리

> 정보보호 관리 (위험관리·BCP·ISMS-P) · 자세한 풀이는 `6정보보호관리.md`를 봐.

### 🔥 이것만은 꼭

- **다중 방어**: 보안은 단일 대책 ❌, 여러 계층을 겹쳐서
- **잔류위험** = 대책 적용 후에도 남는 위험 → **수용 가능한 수준**으로 관리 (완전 제거 ❌)
- **위험 = 잠재적 손실액 × 발생가능성** / 자산 → 취약성(약점) → 위협(공격 원인) → 위험
- **BCP 5단계**: 범위 설정·기획 → **BIA → 복구전략 → 복구계획** → 수행·테스트·유지보수
- ⚠️ **콜드 사이트 RTO = 수 주~수개월** ("수 일~수 주"는 ❌) / 웜 사이트 = 수 일~수 주
- **ISMS-P 4단계** = **기반 마련 → 위험관리 → 운영 → 점검·개선** (기·위·운·점)
- **사이버위기경보**: 관심 → 주의 → **경계** → 심각 (복수 ISP망 장애·마비 = 경계)
- **개인정보취급자**는 고용형태(파견·시간제)와 무관하게 **실제 취급 여부**로 판단

### 📊 한눈에 비교

#### 위험관리
| 용어 | 한 줄 정리 |
|---|---|
| 자산 | 지켜야 하는 것 |
| 취약성 | 공격받기 쉬운 **약점** |
| 위협 | 피해를 줄 수 있는 **공격 원인** |
| 위험 | 위협이 취약점을 공격해 피해가 날 **가능성과 크기** |
| 위험 처리 | **회피 · 이전 · 감소 · 수용** |

- 위험관리 3과정: 위험분석 → 위험평가 → 대책설정
- 위험분석은 간단한 초기분석부터 시작할 수 있음 ⭕ / "보안 계층이 **단일화**된 하나의 대책" ❌

#### BCP · 재해복구
| 단계 | 질문 |
|---|---|
| 사업영향평가(BIA) | 뭐가 중요하지? |
| 복구전략 개발 | 어떻게 살리지? |
| 복구계획 수립 | 구체적으로 어떻게 하지? |

| 사이트 | 준비 상태 | RTO |
|---|---|---|
| 미러 | 거의 동일하게 실시간 복제 | ⚡ 즉시 |
| 핫 | 장비·시스템 미리 준비 | 🔥 수시간 이내 |
| **웜** | 일부만 준비 | **수 일~수 주** |
| **콜드** | 장소·기본설비만 | **수 주~수개월** |

> 🔑 **미러 → 핫 → 웜 → 콜드** = 빠름 → 느림

#### 제품 평가 · ISMS-P
| 항목 | 한 줄 정리 |
|---|---|
| CC 계층구조 | **클래스 → 패밀리 → 컴포넌트 → 엘리먼트** / 컴포넌트를 "선택 가능한 **최대** 단위"라고 하면 ❌ (엘리먼트가 더 세부) |
| 정보보호 정책 통제 목표 | **승인 및 공표 / 체계 / 유지관리** (정책의 **작성방법** ❌) |
| 개발보안 | 개발·시험 ↔ 운영 **분리** · 통제된 이관 · 외주는 계약서에 보안요구사항 / "절차만 수립하면 무방"은 ❌ (실제 보호조치 필요) |
| 주요 직무자 | 직무 기준 정의 · 목록 최신 관리 · 지정 최소화 / "파견·시간제 **제외**"는 ❌ |
| ISMS-P 인증심사 | **최초 · 사후 · 갱신** (보강심사 ❌) |
| 정보보호 사전점검 | **구축 단계**에서 미리 취약점·보호대책 점검 (투자금액 5억원 이상 권고) |

## 7. 법

> 정보보호 법규 & 윤리 · 자세한 풀이는 `7법.md`를 봐.

### 🔥 이것만은 꼭

- **개인위치정보** → 위치정보법 (개인정보보호법 ❌)
- 정보주체는 정보를 제공**받을** 권리 (제공**할** 권리 ❌)
- ⚠️ **개인정보보호위원회** = **국무총리 소속** ("대통령 소속"은 ❌)
- ⚠️ **정보통신기반보호위원회** = 소속 **국무총리**, 위원장 **국무조정실장** ("위원장은 국무총리"는 ❌)
- **가명정보**를 동의 없이 처리 가능 = **통계 · 과학적 연구 · 공익적 기록보존** (상업적 1:1 마케팅 ❌)
- **CCTV 안내판** = 목적 · 장소 · 촬영범위(시간) · 관리책임자 연락처 (**보관기간 ❌**)
- **공개서버** → **DMZ** (내부 서버팜 ❌)
- 법 문제에서 "**모든 / 항상 / 무조건**" 같은 단정 표현은 조건·예외를 의심

### 📊 한눈에 비교

#### 소관 법률 구분
| 법률 | 대표 키워드 |

| 위치정보법 | **개인위치정보** 이용·제공 제한 |
