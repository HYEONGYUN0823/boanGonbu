# 정보보안기사 오답노트 - PKI / OTP / 접근통제 / RSA / 해시 / 암호학

## 1. PKI의 구조 중 여러 개의 인증기관이 계층적으로 구성되어 있지 않고, 독립적으로 운영되는 구조는?

**정답: ① 네트워크 구조**

### 1) 문제 이해하기

먼저 PKI가 무엇인지부터 알아보자.

PKI(Public Key Infrastructure)는 공개키 기반 구조라고 해.

쉽게 말하면 인터넷에서 누군가의 공개키가 진짜인지 확인하고, 안전하게 인증서를 발급하고 관리하기 위한 체계야.

예를 들어 내가 어떤 웹사이트에 접속했을 때 그 웹사이트가 진짜인지 확인해야 하잖아?

이때 인증기관(CA)이 발급한 인증서를 통해 해당 웹사이트의 신원을 확인할 수 있어.

여기서 CA는 Certificate Authority의 약자로, 인증서를 발급하고 관리하는 기관이야.

그렇다면 PKI는 인증기관들을 어떻게 구성하느냐에 따라 구조가 달라질 수 있어.

### 2) PKI의 구조 이해하기

**① 네트워크 구조**

- 여러 인증기관이 계층적으로 연결되지 않고 독립적으로 운영되는 구조야.
- 각 인증기관이 서로 독립적인 관계를 유지하면서 필요한 경우 상호 인증을 수행할 수 있어.
- 한 인증기관이 다른 인증기관의 상위 기관으로 존재하는 계층 구조와 달라.

쉽게 말하면 여러 학교가 있다고 생각해 보자.

A 학교가 B 학교의 상위 학교이고, B 학교가 C 학교의 상위 학교인 관계가 아니라 각 학교가 독립적으로 운영되는 형태야.

**② 계층 구조**

- 인증기관들이 상위 CA와 하위 CA의 관계로 구성되는 구조야.
- 최상위에는 루트 CA가 존재하고, 그 아래에 하위 CA들이 연결되는 형태야.
- 상위 인증기관이 하위 인증기관의 인증서를 발급하거나 관리하는 방식으로 구성돼.

쉽게 말하면 회사의 조직도와 비슷해.

```text
          루트 CA
             |
       --------------
       |            |
     CA A          CA B
       |            |
     CA C          CA D
```

위에서 아래로 계층적인 관계가 형성되어 있지?

**③ 분산 구조**

- 인증기관의 기능이나 관리가 여러 곳에 분산되어 운영되는 형태를 의미해.
- 중앙에 모든 기능이 집중되는 방식과 구분되는 개념이야.
- 문제에서 말하는 독립적인 인증기관들이 계층적으로 연결되지 않은 구조는 네트워크 구조에 해당해.

**④ 복합형 구조**

- 계층 구조와 네트워크 구조 등의 특징을 함께 사용하는 구조야.
- 하나의 구조만 사용하는 것이 아니라 여러 구조를 결합하는 형태라고 이해하면 돼.

### 3) 정답이 ①번인 이유

문제에서 가장 중요한 표현은 다음과 같아.

"계층적으로 구성되어 있지 않고, 독립적으로 운영되는 구조"

상위 CA와 하위 CA의 관계로 연결된 것이 아니라 인증기관들이 독립적으로 운영되는 구조이므로 네트워크 구조가 정답이야.

### 4) 다른 보기가 틀린 이유

- ① 네트워크 구조: 인증기관들이 계층적으로 구성되지 않고 독립적으로 운영되는 구조야.
- ② 계층 구조: 루트 CA를 중심으로 상위 CA와 하위 CA가 계층적으로 연결되는 구조야.
- ③ 분산 구조: 기능이나 관리가 여러 곳에 분산되는 개념이야.
- ④ 복합형 구조: 계층 구조와 네트워크 구조 등을 함께 사용하는 형태야.

### 5) 시험 암기

- 네트워크 구조 = 독립적인 인증기관
- 계층 구조 = 루트 CA 중심의 상하 관계
- 복합형 구조 = 여러 구조의 결합

**핵심 암기:**
독립적인 CA → 네트워크 구조
루트 CA와 하위 CA → 계층 구조

## 2. OTP의 생성 및 인증 방식 중 시간 동기화 방식에 대한 설명으로 옳지 않은 것은?

**정답: ③ 서버와 클라이언트가 카운트값을 동일하게 증가시켜 가며, 카운트 값을 입력값으로 OTP를 생성해 인증하는 방식이다.**

### 1) 문제 이해하기

OTP(One-Time Password)는 일회용 비밀번호야.

일반적인 비밀번호는 한 번 설정하면 계속 사용할 수 있지만, OTP는 인증할 때마다 새로운 비밀번호를 생성해서 사용하는 방식이야.

예를 들어 인터넷 뱅킹에서 로그인하거나 송금할 때 사용하는 일회용 인증번호가 OTP야.

OTP는 생성하는 방식에 따라 여러 종류가 있어.

이번 문제에서는 시간 동기화 방식과 카운터 방식의 차이를 알아야 해.

### 2) OTP 생성 방식 이해하기

**① 시간 동기화 방식 (Time Synchronization)**

- 서버와 클라이언트가 현재 시간을 기준으로 동일한 OTP를 생성하는 방식이야.
- 서버와 클라이언트가 같은 시간 정보를 사용해서 OTP를 만들어.
- 일정 시간이 지나면 새로운 OTP가 생성돼.

예를 들어 OTP 앱에서 6자리 숫자가 표시된다고 생각해 보자.

```text
현재 시간: 12:00

OTP: 123456
```

일정 시간이 지나면 다음과 같이 바뀌는 거야.

```text
현재 시간: 12:01

OTP: 789012
```

실제 OTP는 시간과 비밀키 등을 이용해 계산하기 때문에 위 숫자는 이해를 돕기 위한 예시야.

중요한 점은 서버와 클라이언트의 시간이 서로 맞아야 한다는 거야.

만약 클라이언트의 시간이 서버와 맞지 않으면 서로 다른 OTP를 생성할 수 있기 때문에 인증에 실패할 수 있어.

**② 카운터 동기화 방식 (Counter Synchronization)**

- 서버와 클라이언트가 동일한 카운터 값을 사용해서 OTP를 생성하는 방식이야.
- OTP를 생성할 때마다 카운터 값을 증가시키는 방식이지.
- 시간보다는 카운터 값이 중요해.

예를 들어 다음과 같이 생각하면 돼.

```text
첫 번째 인증
카운터: 1
OTP: 123456

두 번째 인증
카운터: 2
OTP: 789012

세 번째 인증
카운터: 3
OTP: 456789
```

실제 OTP는 비밀키와 카운터 값을 함께 사용해 생성해.

여기서 중요한 차이는 시간 동기화 방식은 현재 시간을 사용하고, 카운터 동기화 방식은 카운터 값을 사용한다는 거야.

### 3) 정답이 ③번인 이유

문제의 ③번은 다음과 같이 설명하고 있어.

"서버와 클라이언트가 카운트값을 동일하게 증가시켜 가며, 카운트 값을 입력값으로 OTP를 생성해 인증하는 방식"

이 설명은 시간 동기화 방식이 아니라 카운터 동기화 방식에 대한 설명이야.

문제는 시간 동기화 방식에 대한 설명 중 옳지 않은 것을 물어봤기 때문에 ③번이 정답이야.

### 4) 다른 보기가 맞는 이유

**① 클라이언트와 서버의 시간 동기화가 정확하지 않으면 인증에 실패한다.**

- 시간 동기화 방식은 양쪽의 시간 정보를 기준으로 OTP를 생성해.
- 따라서 시간이 맞지 않으면 서로 다른 OTP가 만들어질 수 있어.
- 올바른 설명이야.

**② 임의의 입력값이 필요하지 않다.**

- 시간 동기화 방식은 현재 시간과 비밀키 등을 이용해 OTP를 생성해.
- 사용자가 별도의 임의의 숫자를 입력해서 OTP를 생성할 필요는 없어.
- 올바른 설명이야.

**③ 서버와 클라이언트가 카운트값을 동일하게 증가시켜 가며 OTP를 생성한다.**

- 현재 시간을 기준으로 하는 방식이 아니라 카운터 값을 기준으로 하는 방식이야.
- 따라서 시간 동기화 방식에 대한 설명으로는 틀렸어.

**④ 클라이언트는 현재 시각을 입력값으로 OTP를 생성해 서버로 전송한다.**

- 시간 동기화 방식은 현재 시각을 기준으로 OTP를 생성해.
- 따라서 올바른 설명이야.

### 5) 시험 암기

| 구분 | 시간 동기화 방식 | 카운터 동기화 방식 |
|---|---|---|
| 기준 | 현재 시간 | 카운터 값 |
| 특징 | 일정 시간마다 OTP 변경 | 카운터 증가에 따라 OTP 변경 |
| 중요 요소 | 서버와 클라이언트의 시간 일치 | 서버와 클라이언트의 카운터 일치 |

**핵심 암기:**
- 시간 동기화 = 현재 시간
- 카운터 동기화 = 카운터 값
- 시간 동기화 방식에서 시간이 맞지 않으면 인증 실패

## 3. 다음 중 임의적 접근통제(DAC)의 설명으로 옳지 않은 것은?

**정답: ④ 접근제어목록 없이 임의의 주체와 객체 간의 접근통제 관계를 정의한다.**

### 1) 문제 이해하기

먼저 접근통제(Access Control)가 무엇인지 알아보자.

접근통제는 사용자나 프로그램이 특정 정보나 파일에 접근할 수 있는지 제한하는 보안 기술이야.

예를 들어 컴퓨터에 다음과 같은 파일이 있다고 생각해 보자.

```text
비밀문서.txt
```

이 파일을 아무나 열어볼 수 있으면 보안상 문제가 생기겠지?

그래서 접근통제를 통해 누가 파일을 읽고, 수정하고, 삭제할 수 있는지 제한하는 거야.

여기서 DAC는 Discretionary Access Control의 약자로, 임의적 접근통제라고 해.

### 2) DAC란?

DAC는 객체의 소유자가 다른 사용자에게 접근 권한을 부여하거나 제한할 수 있는 접근통제 방식이야.

쉽게 말하면 내가 소유한 파일의 권한을 내가 정하는 방식이야.

예를 들어 내가 다음 파일을 가지고 있다고 생각해 보자.

```text
내 문서.txt
```

내가 이 파일의 소유자라면 다음과 같이 권한을 설정할 수 있어.

```text
나: 읽기, 쓰기 가능
친구 A: 읽기 가능
친구 B: 접근 불가능
```

이처럼 객체의 소유자가 다른 사용자에게 접근 권한을 부여할 수 있는 방식이 DAC야.

### 3) DAC의 특징

**① 접근제어가 객체의 내용과 무관하게 이루어진다.**

- DAC는 객체의 내용 자체보다는 사용자에게 부여된 접근 권한을 기준으로 접근을 제어해.
- 예를 들어 파일 내용이 무엇인지와 관계없이 해당 파일에 읽기 권한이 있는지 확인하는 거야.
- 올바른 설명이야.

**② 권한을 가진 주체가 임의의 타 주체에 의한 객체 접근을 허가할 수 있다.**

- DAC의 가장 중요한 특징이야.
- 객체에 대한 권한을 가진 사용자가 다른 사용자에게 접근 권한을 부여할 수 있어.
- 올바른 설명이야.

**③ 객체에 대한 보호 및 공유가 소유 주체에 의하여 이루어진다.**

- 객체의 소유자가 접근 권한을 관리하는 방식이야.
- 파일의 소유자가 다른 사용자에게 읽기나 쓰기 권한을 부여할 수 있지.
- 올바른 설명이야.

**④ 접근제어목록 없이 임의의 주체와 객체 간의 접근통제 관계를 정의한다.**

- 이 설명이 틀렸어.
- DAC에서는 ACL(Access Control List)을 이용해 객체에 접근할 수 있는 사용자와 권한을 관리할 수 있어.
- 따라서 접근제어목록 없이 접근통제 관계를 정의한다는 설명은 올바르지 않아.

### 4) ACL이란?

ACL은 Access Control List의 약자로 접근제어목록이야.

쉽게 말하면 특정 파일에 누가 어떤 권한을 가지고 있는지 기록한 목록이야.

예를 들어 다음과 같아.

| 사용자 | 읽기 | 쓰기 | 실행 |
|---|---|---|---|
| 사용자 A | O | O | X |
| 사용자 B | O | X | X |
| 사용자 C | X | X | X |

이렇게 객체에 대한 사용자별 접근 권한을 목록으로 관리하는 거야.

### 5) 정답이 ④번인 이유

DAC는 객체의 소유자가 접근 권한을 관리하며, ACL 등을 통해 접근 권한을 설정할 수 있어.

그런데 ④번은 접근제어목록 없이 접근통제 관계를 정의한다고 설명하고 있으므로 틀린 내용이야.

따라서 정답은 ④번이야.

### 6) 시험 암기

- DAC = 임의적 접근통제
- 객체의 소유자가 접근 권한을 결정
- 다른 사용자에게 접근 권한을 부여할 수 있음
- ACL을 이용해 사용자별 권한 관리 가능

**핵심 암기:**
DAC = 소유자가 권한을 정한다.

## 4. RSA 알고리즘에서 N=2419, φ(N)=2320일 때 적절한 p+q의 값은?

**정답: ② 100**

### 1) 문제 이해하기

이번 문제는 수학이 들어가서 처음 보면 어려울 수 있어.

하지만 걱정하지 마.

복잡한 계산을 하는 문제가 아니라 RSA에서 사용하는 공식 하나만 알면 풀 수 있는 문제야.

문제에서 주어진 값은 다음과 같아.

```text
N = 2419

φ(N) = 2320
```

그리고 다음 조건이 있어.

```text
N = p × q
```

여기서 p와 q는 RSA에서 사용하는 두 개의 소수야.

우리가 구해야 하는 값은 다음과 같아.

```text
p + q = ?
```

### 2) 먼저 φ(N)이 무엇인지 알아보자

φ(N)은 오일러 피 함수(Euler's Totient Function)라고 해.

RSA에서는 p와 q가 서로 다른 소수일 때 다음과 같은 공식이 성립해.

```text
φ(N) = (p - 1) × (q - 1)
```

문제에서 N이 p × q라고 주어졌으므로 이 공식을 사용할 수 있어.

이제 식을 전개해 보자.

```text
φ(N) = (p - 1) × (q - 1)
```

괄호를 풀면 다음과 같아.

```text
φ(N) = pq - p - q + 1
```

그런데 문제에서 다음과 같이 주어졌지?

```text
N = pq
```

그러므로 pq 대신 N을 넣을 수 있어.

```text
φ(N) = N - p - q + 1
```

이제 우리가 구하고 싶은 p + q만 남도록 식을 정리하면 돼.

```text
p + q = N - φ(N) + 1
```

이게 이번 문제에서 가장 중요한 공식이야.

### 3) 실제 숫자를 대입해 보자

문제에서 주어진 값은 다음과 같아.

```text
N = 2419

φ(N) = 2320
```

공식에 그대로 넣으면 돼.

```text
p + q = N - φ(N) + 1
```

숫자를 대입하면 다음과 같아.

```text
p + q = 2419 - 2320 + 1
```

먼저 빼기를 해보자.

```text
2419 - 2320 = 99
```

여기에 1을 더하면?

```text
99 + 1 = 100
```

따라서 정답은 다음과 같아.

```text
p + q = 100
```

정답은 ②번이야.

### 4) 왜 이런 공식이 나오는 걸까?

한 번 더 쉽게 이해해 보자.

처음 공식은 다음과 같았어.

```text
φ(N) = (p - 1) × (q - 1)
```

괄호를 풀면 다음과 같지.

```text
φ(N) = pq - p - q + 1
```

그런데 pq는 N과 같아.

```text
N = pq
```

그래서 다음과 같이 바뀌는 거야.

```text
φ(N) = N - p - q + 1
```

여기서 p와 q를 한쪽으로 옮기면?

```text
p + q = N - φ(N) + 1
```

결국 p와 q를 각각 구하지 않아도 합계를 바로 구할 수 있는 거야.

### 5) 시험 암기

RSA에서 p와 q가 서로 다른 소수이고 N = pq일 때:

```text
N = p × q
```

```text
φ(N) = (p - 1) × (q - 1)
```

```text
p + q = N - φ(N) + 1
```

**이번 문제의 계산:**

```text
p + q = 2419 - 2320 + 1

p + q = 100
```

**핵심 암기:**
- p × q = N
- (p - 1) × (q - 1) = φ(N)
- p + q = N - φ(N) + 1

※ 이 공식은 RSA에서 p와 q가 서로 다른 소수라는 조건을 전제로 해.

## 5. 다음 내용에서 설명하고 있는 것은?

**정답: ② SHA**

### 1) 문제 이해하기

문제에서 설명하는 특징을 먼저 살펴보자.

- 1993년 미국 NIST에서 개발
- 미국표준 FIPS PUB 180으로 공포
- 160비트 출력
- 512비트 블록 단위 처리
- 4라운드, 80단계
- 전용 해시함수

이 특징을 가진 것은 SHA야.

### 2) SHA란?

SHA(Secure Hash Algorithm)는 데이터를 일정한 길이의 해시값으로 변환하는 해시 알고리즘이야.

쉽게 말하면 어떤 길이의 데이터를 넣더라도 정해진 길이의 결과값으로 바꿔주는 기술이야.

예를 들어 다음과 같은 데이터가 있다고 생각해 보자.

```text
안녕하세요
```

이 데이터를 SHA 알고리즘에 넣으면 일정한 길이의 해시값이 만들어져.

원본 데이터가 조금이라도 바뀌면 해시값도 달라질 수 있어.

이런 특징을 이용해서 데이터가 변경되었는지 확인할 수 있어.

### 3) 문제에 나온 SHA의 특징

문제에서 설명하는 것은 최초의 SHA 계열인 SHA-0이야.

주요 특징은 다음과 같아.

| 항목 | 특징 |
|---|---|
| 개발 기관 | 미국 NIST |
| 발표 연도 | 1993년 |
| 표준 | FIPS PUB 180 |
| 해시 출력 길이 | 160비트 |
| 블록 크기 | 512비트 |
| 라운드 | 4라운드 |
| 전체 단계 | 80단계 |

문제에서 제시한 숫자들이 SHA-0의 특징과 일치해.

### 4) 다른 보기가 틀린 이유

**① MD5**

- MD5는 128비트 해시값을 생성하는 해시 알고리즘이야.
- 512비트 블록 단위로 처리하지만, 문제에서 제시한 160비트 출력과 일치하지 않아.

**② SHA**

- SHA-0은 160비트 해시값을 생성해.
- 512비트 블록 단위로 처리하고 80단계로 구성돼.
- 문제의 설명과 일치하므로 정답이야.

**③ RIPEMD-160**

- RIPEMD-160은 160비트 해시값을 생성하는 해시 알고리즘이야.
- 이름에 160이 들어가는 이유도 출력 길이가 160비트이기 때문이야.
- 하지만 문제에서 설명하는 1993년 NIST의 FIPS PUB 180 표준과는 달라.

※ 문제에 적힌 `PIPEMD-160`은 `RIPEMD-160`의 오타로 보여.

**④ MD4**

- MD4는 128비트 해시값을 생성하는 해시 알고리즘이야.
- SHA와는 개발 배경과 구조가 달라.
- 문제에서 제시한 특징과 일치하지 않아.

### 5) 시험 암기

| 알고리즘 | 해시 출력 길이 |
|---|---|
| MD4 | 128비트 |
| MD5 | 128비트 |
| SHA-0 | 160비트 |
| SHA-1 | 160비트 |
| RIPEMD-160 | 160비트 |

**핵심 암기:**
- MD4 = 128비트
- MD5 = 128비트
- SHA-0 = 160비트
- SHA-1 = 160비트
- SHA-0은 1993년 NIST, FIPS PUB 180

※ SHA-0은 이후 SHA-1로 대체되었고, SHA-1 역시 충돌 공격이 실증되어 현재는 안전한 용도로 권장되지 않아. 시험에서는 문제에 나온 역사적 특징을 기준으로 기억하면 돼.

## 6. 다음 중 이산로그문제에 기반한 암호 알고리즘이 안전한 이유에 대한 설명으로 옳지 않은 것은?

**정답: ③ 쇼어 알고리즘을 사용하면 소인수 분해와 이산 로그 문제를 해결할 수 있는 방법이 없다.**

### 1) 문제 이해하기

이번 문제는 이산로그문제와 쇼어 알고리즘을 이해해야 해.

먼저 이산로그문제부터 알아보자.

이산로그문제는 큰 수를 이용한 암호 알고리즘의 안전성과 관련된 수학적 문제야.

대표적으로 다음과 같은 형태가 있어.

```text
g^x ≡ h (mod p)
```

여기서 우리가 알고 싶은 것은 x야.

g, h, p를 알고 있더라도 x를 구하는 것이 매우 어려울 수 있다는 특징을 이용하는 거야.

### 2) 이산로그문제 쉽게 이해하기

일반적인 계산을 먼저 생각해 보자.

```text
2^5 = 32
```

2를 5번 곱하면 32가 나온다는 것을 알고 있지?

이런 계산은 어렵지 않아.

그런데 반대로 생각해 보자.

```text
2^x ≡ 32 (mod p)
```

여기서 x를 찾아야 한다면 어떻게 될까?

작은 숫자라면 하나씩 대입해 보면 되겠지만, 암호 알고리즘에서 사용하는 수는 매우 커.

따라서 큰 수를 사용하는 경우 x를 찾아내는 것이 매우 어려워질 수 있어.

이것이 이산로그문제의 핵심이야.

※ 위의 예시는 개념을 이해하기 위한 것이고, 실제 암호 알고리즘에서는 큰 소수와 유한군 등의 수학적 구조를 사용해.

### 3) 이산로그문제가 왜 암호학에서 중요할까?

암호 알고리즘은 공격자가 비밀정보를 알아내기 어렵도록 만들어야 해.

이산로그문제에 기반한 암호 알고리즘은 다음과 같은 특징을 이용해.

- 정방향 계산은 비교적 빠르게 수행할 수 있어.
- 반대로 결과만 보고 원래의 지수를 찾아내는 것은 어려워.
- 큰 수를 사용하면 일반적인 컴퓨터로 문제를 해결하는 데 매우 많은 시간이 필요해.

이런 계산의 비대칭성을 이용하는 거야.

### 4) 쇼어 알고리즘이란?

여기서 가장 중요한 개념이 쇼어 알고리즘(Shor's Algorithm)이야.

쇼어 알고리즘은 양자 컴퓨터에서 실행되는 알고리즘으로, 큰 수의 소인수 분해와 이산로그문제를 효율적으로 해결할 수 있어.

일반적인 컴퓨터에서는 매우 어려운 수학 문제라도 충분히 강력한 양자 컴퓨터에서는 쇼어 알고리즘을 통해 효율적으로 해결할 수 있는 거야.

따라서 쇼어 알고리즘은 RSA뿐 아니라 이산로그문제에 기반한 암호 알고리즘에도 큰 위협이 돼.

대표적인 이산로그 기반 암호 알고리즘에는 다음과 같은 것들이 있어.

- Diffie-Hellman 키 교환
- ElGamal 암호
- DSA 전자서명

### 5) 정답이 ③번인 이유

③번에서는 다음과 같이 설명하고 있어.

"쇼어 알고리즘을 사용하면 소인수 분해와 이산 로그 문제를 해결할 수 있는 방법이 없다."

이 설명은 틀렸어.

실제로 쇼어 알고리즘은 소인수 분해와 이산로그문제를 효율적으로 해결할 수 있는 양자 알고리즘이야.

따라서 쇼어 알고리즘으로 해결할 방법이 없다는 설명은 잘못됐어.

정답은 ③번이야.

### 6) 다른 보기가 맞는 이유

**① 이산 로그 문제를 풀기 위해서는 지수 시간이나 서브 지수 시간이 걸리기 때문에 공격자가 큰 소수를 사용해 이산 로그 문제를 풀기 위해서는 막대한 시간이 소요된다.**

- 일반적인 고전 컴퓨터에서 큰 수를 사용하는 이산로그문제는 해결하기 어려워.
- 큰 수를 사용할수록 공격자가 문제를 푸는 데 많은 계산이 필요해.
- 따라서 암호의 안전성과 관련된 설명으로 맞아.

**② 이산 로그 문제를 해결할 수 있는 알고리즘이 존재하기는 하나 일반적으로 큰 소수를 사용하는 경우에는 느리고 비효율적이기 때문에 이산 로그 문제를 풀기 위한 효율적인 알고리즘이 부재하다.**

- 고전 컴퓨터에서도 이산로그문제를 해결하는 알고리즘은 존재해.
- 하지만 적절한 큰 수와 안전한 매개변수를 사용하면 일반적으로 계산이 매우 어려워져.
- 따라서 고전 컴퓨터 기준으로 효율적인 해결 방법이 없다는 취지의 설명이야.

**③ 쇼어 알고리즘을 사용하면 소인수 분해와 이산 로그 문제를 해결할 수 있는 방법이 없다.**

- 쇼어 알고리즘은 양자 컴퓨터를 이용해 소인수 분해와 이산로그문제를 효율적으로 해결할 수 있어.
- 따라서 틀린 설명이야.

**④ 그룹 G=F_q의 원소 g가 오더 N이라고 할 때 이산 로그 문제 g^x = h는 p가 스무스 소수나 p ≡ 3(mod 4)이고 a가 모듈로 p에 대한 이차잉여일 때 비교적 쉽게 풀릴 수 있다.**

- 이산로그문제는 사용하는 군의 구조와 매개변수에 따라 난이도가 달라져.
- 특히 군의 차수에 작은 소인수들이 많이 존재하는 경우에는 Pohlig-Hellman 알고리즘 등을 이용해 이산로그문제를 효율적으로 풀 수 있어.
- 이런 경우를 스무스한 군의 차수와 관련지어 이해하면 돼.

※ ④번은 문제에 적힌 수학적 조건만으로 일반적인 이산로그문제가 쉽게 풀린다고 단정하기는 어려워. 특히 `p ≡ 3 (mod 4)`와 이차잉여라는 조건만으로 이산로그문제가 쉬워지는 것은 아니야. 출제된 정답 ③번은 쇼어 알고리즘에 대한 명백한 오류를 지적하는 보기라는 점에서 기억하면 돼.

### 7) 시험 암기

- 이산로그문제 = g^x ≡ h (mod p)에서 x를 구하는 문제
- 큰 수를 사용하면 고전 컴퓨터로 해결하기 어려움
- 쇼어 알고리즘 = 양자 컴퓨터에서 소인수 분해와 이산로그문제를 효율적으로 해결
- RSA = 소인수 분해 문제와 관련
- Diffie-Hellman = 이산로그문제와 관련
- ElGamal = 이산로그문제와 관련
- DSA = 이산로그문제와 관련

**핵심 암기:**
쇼어 알고리즘은 소인수 분해와 이산로그문제를 해결할 수 있다.

## 7. 다음 중 NIST에서 정의하고 있는 RBAC의 하위 유형으로 옳지 않은 것은?

**정답: ④ Clustered RBAC**

### 1) 문제 이해하기

먼저 RBAC가 무엇인지 알아보자.

RBAC(Role-Based Access Control)는 역할 기반 접근통제야.

쉽게 말하면 사용자에게 직접 권한을 하나씩 부여하는 것이 아니라, 사용자의 역할에 따라 권한을 부여하는 방식이야.

예를 들어 회사에 다음과 같은 직책이 있다고 생각해 보자.

```text
관리자
직원
인턴
```

각 역할에 따라 접근할 수 있는 정보가 달라지는 거야.

| 역할 | 접근 권한 |
|---|---|
| 관리자 | 모든 관리 기능 |
| 직원 | 일반 업무 기능 |
| 인턴 | 제한된 업무 기능 |

이처럼 사용자의 역할을 기준으로 접근 권한을 관리하는 방식이 RBAC야.

### 2) NIST에서 정의한 RBAC 유형

NIST에서 정의하는 대표적인 RBAC 모델은 다음과 같아.

**① Flat RBAC**

- 가장 기본적인 RBAC 구조야.
- 사용자에게 역할을 부여하고, 역할에 권한을 연결하는 방식이야.
- 역할 간의 계층 관계는 없어.

예를 들어 다음과 같아.

```text
사용자 A → 관리자 역할
사용자 B → 직원 역할
사용자 C → 인턴 역할
```

**② Hierarchical RBAC**

- 역할 사이에 상하 관계를 설정하는 방식이야.
- 상위 역할은 하위 역할의 권한을 상속받을 수 있어.

예를 들어 다음과 같아.

```text
       관리자
          |
        직원
          |
        인턴
```

관리자는 직원과 인턴이 가진 권한을 포함할 수 있는 구조야.

**③ Constrained RBAC**

- 역할에 제약 조건을 추가하는 방식이야.
- 특정 역할을 동시에 수행하지 못하도록 제한하거나, 권한 충돌을 방지하는 데 사용돼.
- 임무 분리(Separation of Duty)와 관련이 있어.

예를 들어 한 사람이 돈을 지급하는 역할과 지급을 승인하는 역할을 동시에 가지지 못하도록 제한할 수 있어.

**④ Symmetric RBAC**

- 사용자와 역할 사이의 관계뿐 아니라 역할과 권한 사이의 관계도 관리할 수 있도록 확장된 유형이야.
- 사용자에게 역할을 부여하는 관계와 역할에 권한을 부여하는 관계를 대칭적으로 관리할 수 있어.

### 3) 정답이 ④번인 이유

문제의 보기 중 NIST에서 정의한 RBAC 하위 유형이 아닌 것은 Clustered RBAC야.

NIST에서 정의하는 대표적인 유형은 다음 네 가지야.

1. Flat RBAC
2. Hierarchical RBAC
3. Constrained RBAC
4. Symmetric RBAC

따라서 Clustered RBAC는 해당 유형에 포함되지 않으므로 정답은 ④번이야.

### 4) 다른 보기가 맞는 이유

- ① Symmetric RBAC: NIST에서 정의한 RBAC 유형이야.
- ② Flat RBAC: 가장 기본적인 RBAC 유형이야.
- ③ Constrained RBAC: 역할에 제약 조건을 적용하는 RBAC 유형이야.
- ④ Clustered RBAC: NIST에서 정의한 대표적인 RBAC 유형이 아니야.

### 5) 시험 암기

NIST RBAC 4가지 유형:

- Flat RBAC
- Hierarchical RBAC
- Constrained RBAC
- Symmetric RBAC

**핵심 암기:**
Flat / Hierarchical / Constrained / Symmetric

Clustered는 포함되지 않아.

## 8. 다음 중 Active Attack과 Passive Attack을 순서대로 나열한 것은?

**정답: ④ 삭제공격 - 전송파일 도청**

### 1) 문제 이해하기

먼저 Active Attack과 Passive Attack이 무엇인지 알아보자.

이 둘의 차이를 이해하려면 공격자가 통신 과정에서 어떤 행동을 하는지 생각하면 돼.

**Active Attack (능동적 공격)**

- 공격자가 통신이나 데이터에 직접 개입하는 공격이야.
- 데이터를 수정하거나 삭제하거나 새로운 데이터를 삽입할 수 있어.
- 통신의 정상적인 흐름을 방해하는 것이 특징이야.

**Passive Attack (수동적 공격)**

- 공격자가 통신에 직접 개입하지 않고 정보를 몰래 관찰하거나 수집하는 공격이야.
- 데이터를 수정하거나 삭제하지 않고 내용을 엿보는 것이 특징이야.
- 대표적으로 도청이나 트래픽 분석이 있어.

### 2) Active Attack 이해하기

능동적 공격은 공격자가 데이터에 직접 손을 대는 방식이야.

대표적인 공격은 다음과 같아.

**① 삽입공격**

- 공격자가 정상적인 통신에 악의적인 데이터를 추가하는 공격이야.
- 원래 없던 메시지나 데이터를 끼워 넣는 거지.

**② 삭제공격**

- 공격자가 전송 중인 데이터나 메시지를 삭제하는 공격이야.
- 정상적인 통신을 방해할 수 있어.

**③ 수정공격**

- 공격자가 전송되는 데이터를 임의로 변경하는 공격이야.
- 원래 전달하려던 내용과 다른 내용으로 바꿀 수 있어.

**④ 재생공격**

- 공격자가 과거에 전송된 정상적인 메시지를 다시 전송하는 공격이야.
- 예를 들어 정상적인 인증 메시지를 가로챈 다음 나중에 다시 전송하는 방식이지.

### 3) Passive Attack 이해하기

수동적 공격은 공격자가 통신 내용을 몰래 관찰하는 방식이야.

대표적인 공격은 다음과 같아.

**① 전송파일 도청**

- 네트워크를 통해 전송되는 파일이나 데이터를 몰래 확인하는 공격이야.
- 데이터 자체를 변경하지는 않아.

**② 트래픽 분석**

- 통신 내용 자체를 확인하지 못하더라도 통신량, 통신 시간, 통신 상대 등을 분석하는 공격이야.
- 누가 누구와 통신하는지 등의 정보를 알아낼 수 있어.

### 4) 정답이 ④번인 이유

문제는 Active Attack과 Passive Attack을 순서대로 나열하라고 했어.

④번은 다음과 같아.

```text
삭제공격 - 전송파일 도청
```

첫 번째인 삭제공격은 데이터를 직접 삭제하는 공격이므로 Active Attack이야.

두 번째인 전송파일 도청은 데이터를 변경하지 않고 몰래 확인하는 공격이므로 Passive Attack이야.

따라서 정답은 ④번이야.

### 5) 다른 보기가 틀린 이유

**① 트래픽 분석공격 - 전송파일 도청**

- 트래픽 분석공격 = Passive Attack
- 전송파일 도청 = Passive Attack
- 둘 다 수동적 공격이므로 Active → Passive 순서가 아니야.

**② 재생공격 - 메시지 변조 공격**

- 재생공격 = Active Attack
- 메시지 변조 공격 = Active Attack
- 둘 다 능동적 공격이야.

**③ 삽입공격 - 삭제공격**

- 삽입공격 = Active Attack
- 삭제공격 = Active Attack
- 둘 다 능동적 공격이야.

**④ 삭제공격 - 전송파일 도청**

- 삭제공격 = Active Attack
- 전송파일 도청 = Passive Attack
- 능동적 공격 다음에 수동적 공격이 나오므로 정답이야.

### 6) 시험 암기

| 구분 | 공격 종류 |
|---|---|
| Active Attack | 삽입, 삭제, 수정, 재생 |
| Passive Attack | 도청, 트래픽 분석 |

**핵심 암기:**
- 데이터를 건드리면 Active
- 몰래 훔쳐보면 Passive

## 9. 다음 중 접근통제 보안 모델 중 클락 윌슨(Clark-Wilson) 모델에 대한 설명으로 옳지 않은 것은?

**정답: ② 기밀성을 확보하기 위해 개발된 보안모델이다.**

### 1) 문제 이해하기

먼저 Clark-Wilson 모델이 무엇인지 알아보자.

Clark-Wilson 모델은 데이터의 무결성을 보장하기 위해 만들어진 보안 모델이야.

여기서 무결성은 데이터가 허가되지 않은 방식으로 변경되거나 훼손되지 않고 정확하게 유지되는 것을 의미해.

예를 들어 은행 계좌에 100만 원이 있다고 생각해 보자.

그런데 누군가 허가 없이 계좌 잔액을 1억 원으로 변경한다면 문제가 생기겠지?

이런 식으로 데이터가 임의로 변경되는 것을 방지하고, 정해진 절차에 따라 데이터가 처리되도록 하는 것이 Clark-Wilson 모델의 핵심이야.

### 2) Clark-Wilson 모델의 특징

**① 무결성 중심의 보안 모델**

Clark-Wilson 모델은 기밀성이 아니라 무결성을 보장하기 위해 만들어진 모델이야.

기밀성은 허가받지 않은 사람이 정보를 보지 못하게 하는 것이고, 무결성은 허가받지 않은 변경을 막는 것이야.

예를 들어 다음과 같아.

```text
기밀성:
허가받지 않은 사람이 정보를 읽지 못하게 한다.

무결성:
허가받지 않은 사람이 정보를 변경하지 못하게 한다.
```

Clark-Wilson은 두 번째인 무결성에 초점을 맞춰.

**② 임무 분할 (Separation of Duty)**

- 하나의 사람이 모든 작업을 마음대로 처리하지 못하도록 역할을 분리하는 원칙이야.
- 서로 다른 사람이 작업을 나누어 수행하도록 해서 부정행위나 실수를 방지할 수 있어.

예를 들어 은행에서 돈을 지급하는 업무를 생각해 보자.

```text
직원 A: 송금 요청
직원 B: 송금 승인
```

한 사람이 송금 요청과 승인을 모두 할 수 있다면 부정한 송금이 발생할 위험이 커지겠지?

그래서 역할을 분리하는 거야.

**③ 제한 인터페이스 (Constrained Interface)**

- 사용자가 데이터에 직접 접근하지 못하도록 제한하는 방식이야.
- 정해진 프로그램이나 절차를 통해서만 데이터를 변경할 수 있도록 해.

쉽게 말하면 사용자가 데이터베이스에 직접 들어가서 잔액을 바꾸는 것이 아니라, 정해진 은행 프로그램을 통해서만 잔액을 변경할 수 있도록 하는 거야.

**④ 응용 프로그램을 통한 데이터 접근**

- 사용자는 객체나 데이터에 직접 접근할 수 없어.
- 정해진 응용 프로그램(Application)을 통해서만 접근할 수 있어.
- 이렇게 하면 데이터가 임의로 변경되는 것을 방지할 수 있어.

### 3) 정답이 ②번인 이유

문제에서 ②번은 다음과 같이 설명하고 있어.

"기밀성을 확보하기 위해 개발된 보안모델이다."

하지만 Clark-Wilson 모델은 기밀성이 아니라 무결성을 보장하기 위해 개발된 모델이야.

따라서 ②번이 틀린 설명이야.

### 4) 다른 보기가 맞는 이유

**① 효율적인 업무처리와 임무분할의 원칙의 사용을 통해 무결성을 보장하기 위한 효과적인 수단을 제공한다.**

- Clark-Wilson 모델은 무결성을 보장하기 위해 임무 분할 등의 원칙을 사용해.
- 올바른 설명이야.

**② 기밀성을 확보하기 위해 개발된 보안모델이다.**

- Clark-Wilson은 기밀성이 아니라 무결성을 보장하기 위한 모델이야.
- 틀린 설명이야.

**③ 제한 인터페이스 모델이라고도 부른다.**

- Clark-Wilson 모델은 제한된 인터페이스를 통해 데이터에 접근하도록 하는 특징이 있어.
- 올바른 설명이야.

**④ 사용자는 객체(정보)에 직접 접근을 할 수 없고 Application을 통해서만 접근이 가능하다.**

- 데이터에 직접 접근하는 것을 제한하고 정해진 프로그램을 통해서만 접근하도록 해.
- 올바른 설명이야.

### 5) 시험 암기

- Clark-Wilson = 무결성
- 임무 분할(Separation of Duty)
- 제한 인터페이스(Constrained Interface)
- Application을 통한 데이터 접근
- 사용자의 직접적인 데이터 접근 제한

**핵심 암기:**
Clark-Wilson = 무결성 모델

기밀성 모델이 아니야.

## 10. 다음 중 전달하고자 하는 메시지를 암호화하여 한 사람을 통해서 보내고, 암호화 키는 다른 사람에게 가져가게 하는 것을 암호학적으로 구현한 것은?

**정답: ① 전자봉투**

### 1) 문제 이해하기

문제에서 가장 중요한 표현은 다음과 같아.

- 전달하고자 하는 메시지를 암호화
- 암호화된 메시지는 한 사람을 통해서 전달
- 암호화 키는 다른 사람에게 전달

즉, 메시지와 암호화 키를 서로 다른 경로로 전달하는 방식이야.

이것을 암호학적으로 구현한 것이 전자봉투야.

### 2) 전자봉투란?

전자봉투(Digital Envelope)는 대칭키 암호화와 공개키 암호화를 함께 사용하는 방식이야.

먼저 두 가지 암호화 방식을 이해해야 해.

**① 대칭키 암호화**

- 암호화할 때 사용하는 키와 복호화할 때 사용하는 키가 동일한 방식이야.
- 같은 키를 사용해서 데이터를 암호화하고 복호화해.

예를 들어 다음과 같아.

```text
암호화 키: ABC123

평문: 안녕하세요
      |
      v
암호화
      |
      v
암호문: X7F92A
```

암호문을 다시 원래 내용으로 바꾸려면 동일한 키인 ABC123이 필요해.

문제는 이 키를 상대방에게 어떻게 안전하게 전달하느냐는 거야.

**② 공개키 암호화**

공개키 암호화는 공개키와 개인키라는 서로 다른 키를 사용하는 방식이야.

- 공개키: 다른 사람에게 공개할 수 있는 키
- 개인키: 본인만 가지고 있어야 하는 비밀 키

일반적인 공개키 암호화에서는 상대방의 공개키로 암호화하면 상대방의 개인키로 복호화할 수 있어.

### 3) 전자봉투의 동작 과정

전자봉투는 이 두 가지 암호화 방식을 함께 사용해.

예를 들어 내가 친구에게 중요한 문서를 보내려고 한다고 생각해 보자.

**1단계: 대칭키 생성**

먼저 메시지를 암호화할 대칭키를 하나 생성해.

```text
대칭키: ABC123
```

**2단계: 메시지 암호화**

생성한 대칭키를 사용해서 메시지를 암호화해.

```text
원본 메시지
    |
    v
대칭키 ABC123으로 암호화
    |
    v
암호문 생성
```

**3단계: 대칭키 암호화**

이제 생성한 대칭키를 상대방의 공개키로 암호화해.

```text
대칭키 ABC123
       |
       v
상대방의 공개키로 암호화
       |
       v
암호화된 대칭키
```

**4단계: 암호문과 암호화된 대칭키 전달**

이제 상대방에게 다음 두 가지를 전달해.

```text
① 암호화된 메시지
② 공개키로 암호화된 대칭키
```

**5단계: 상대방이 복호화**

상대방은 자신의 개인키로 암호화된 대칭키를 복호화해.

그러면 원래 대칭키인 ABC123을 얻을 수 있어.

이후 그 대칭키로 암호화된 메시지를 복호화하면 원래 내용을 확인할 수 있어.

### 4) 전자봉투를 사용하는 이유

대칭키 암호화는 일반적으로 데이터 암호화가 빠르다는 장점이 있어.

하지만 대칭키를 상대방에게 안전하게 전달해야 한다는 문제가 있어.

반면 공개키 암호화는 키를 안전하게 전달하는 데 유용하지만, 대칭키 암호화에 비해 일반적으로 처리 속도가 느려.

그래서 두 가지 방식을 결합하는 거야.

- 실제 메시지 = 대칭키로 암호화
- 대칭키 = 상대방의 공개키로 암호화

이렇게 하면 대칭키의 빠른 처리 속도와 공개키 암호화의 키 전달 장점을 함께 사용할 수 있어.

### 5) 정답이 ①번인 이유

문제에서 메시지와 암호화 키를 서로 다른 경로로 전달하는 방식을 설명하고 있어.

전자봉투는 메시지를 대칭키로 암호화하고, 그 대칭키를 상대방의 공개키로 암호화해서 함께 전달하는 방식이야.

따라서 정답은 ①번이야.

### 6) 다른 보기가 틀린 이유

**① 전자봉투**

- 메시지는 대칭키로 암호화해.
- 대칭키는 상대방의 공개키로 암호화해.
- 두 가지 암호화 방식을 함께 사용하므로 정답이야.

**② 이중서명**

- 전자상거래에서 주문 정보와 결제 정보를 안전하게 연결하기 위해 사용하는 전자서명 방식이야.
- 대표적으로 SET(Secure Electronic Transaction)에서 사용돼.
- 메시지와 암호화 키를 따로 전달하는 방식이 아니야.

**③ 전자서명**

- 메시지를 보낸 사람이 누구인지 확인하고, 메시지가 변조되지 않았는지 검증하기 위한 기술이야.
- 인증, 무결성, 부인방지와 관련이 있어.
- 메시지와 암호화 키를 따로 전달하는 전자봉투와는 목적이 달라.

**④ 은닉서명**

- 서명자가 서명할 내용의 실제 내용을 알지 못하는 상태에서 서명할 수 있도록 하는 방식이야.
- 서명자의 서명을 받으면서도 메시지의 내용을 숨길 수 있어.
- 전자봉투와는 다른 개념이야.

### 7) 시험 암기

- 전자봉투 = 대칭키 + 공개키 암호화
- 메시지 = 대칭키로 암호화
- 대칭키 = 수신자의 공개키로 암호화
- 수신자 = 개인키로 대칭키 복호화 후 메시지 복호화

**핵심 암기:**
메시지는 대칭키, 대칭키는 공개키 → 전자봉투

# 시험 직전 핵심 암기 노트

## 1. PKI

- 네트워크 구조 = 인증기관들이 독립적으로 운영
- 계층 구조 = 루트 CA를 중심으로 상하 관계 형성
- 복합형 구조 = 여러 구조 결합

## 2. OTP

- 시간 동기화 = 현재 시간을 기준으로 OTP 생성
- 카운터 동기화 = 카운터 값을 기준으로 OTP 생성
- 시간 동기화 방식은 서버와 클라이언트의 시간이 맞아야 함

## 3. DAC

- DAC = 임의적 접근통제
- 객체의 소유자가 접근 권한을 결정
- 다른 사용자에게 권한을 부여할 수 있음
- ACL을 통해 사용자별 접근 권한 관리

## 4. RSA

- N = p × q
- φ(N) = (p - 1) × (q - 1)
- p + q = N - φ(N) + 1

이번 문제:
- N = 2419
- φ(N) = 2320
- p + q = 2419 - 2320 + 1 = 100

## 5. 해시 알고리즘

- MD4 = 128비트
- MD5 = 128비트
- SHA-0 = 160비트
- SHA-1 = 160비트
- RIPEMD-160 = 160비트

## 6. 이산로그문제

- 이산로그문제 = g^x ≡ h (mod p)에서 x를 구하는 문제
- 큰 수를 사용하면 고전 컴퓨터에서 계산하기 어려움
- 쇼어 알고리즘 = 양자 컴퓨터에서 소인수 분해와 이산로그문제를 효율적으로 해결

## 7. RBAC

NIST에서 정의한 RBAC 유형:
- Flat RBAC
- Hierarchical RBAC
- Constrained RBAC
- Symmetric RBAC

Clustered RBAC는 포함되지 않음.

## 8. Active Attack / Passive Attack

- Active = 삽입, 삭제, 수정, 재생
- Passive = 도청, 트래픽 분석

기억하기:
- 데이터를 직접 건드리면 Active
- 데이터를 몰래 관찰하면 Passive

## 9. Clark-Wilson

- 무결성 중심 보안 모델
- 임무 분할(Separation of Duty)
- 제한 인터페이스(Constrained Interface)
- Application을 통한 데이터 접근
- 기밀성 모델이 아님

## 10. 전자봉투

- 메시지 = 대칭키로 암호화
- 대칭키 = 수신자의 공개키로 암호화
- 수신자 = 개인키로 대칭키를 복호화

# 이번 문제에서 특히 기억해야 할 것

1. PKI의 네트워크 구조는 인증기관들이 독립적으로 운영되는 구조야.

2. OTP 시간 동기화 방식은 현재 시간, 카운터 동기화 방식은 카운터 값이 기준이야.

3. DAC는 객체의 소유자가 접근 권한을 결정하고 ACL을 이용해 관리할 수 있어.

4. RSA에서 p + q를 구하는 공식은 N - φ(N) + 1이야.

5. SHA-0은 1993년 NIST에서 발표한 160비트 해시 알고리즘이야.

6. 쇼어 알고리즘은 소인수 분해와 이산로그문제를 효율적으로 해결할 수 있어.

7. NIST RBAC 유형은 Flat, Hierarchical, Constrained, Symmetric이야.

8. Active Attack은 데이터에 직접 개입하고, Passive Attack은 데이터를 몰래 관찰해.

9. Clark-Wilson은 기밀성이 아니라 무결성을 보장하기 위한 모델이야.

10. 전자봉투는 메시지를 대칭키로 암호화하고, 대칭키를 수신자의 공개키로 암호화하는 방식이야.
