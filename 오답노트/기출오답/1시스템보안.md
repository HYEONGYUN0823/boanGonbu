
# 기출문제 오답노트 (시스템 보안)

## 1. 사이버 킬체인(Cyber Kill Chain)의 단계

**정답: 1번**

### 핵심 개념
사이버 킬체인은 해커가 공격을 시작해서 목적을 달성하기까지의 7단계 과정이다.

쉽게 말하면 도둑이 집에 침입하는 과정이라고 생각하면 된다.

### 사이버 킬체인 7단계

1. **정찰(Reconnaissance)**

   공격할 대상의 정보를 조사하는 단계이다.

   예를 들어 도둑이 집의 위치와 경비 상태를 조사하는 것과 같다.

2. **무기화(Weaponization)**

   공격에 사용할 악성코드나 도구를 준비하는 단계이다.

   예를 들어 침입할 때 사용할 도구를 준비하는 것이다.

3. **전달(Delivery)**

   준비한 악성코드를 목표에게 전달하는 단계이다.

   예를 들어 악성 파일이 담긴 이메일을 보내는 것이다.

4. **악용(Exploitation)**

   시스템의 취약점을 이용해서 공격하는 단계이다.

   예를 들어 잠겨 있지 않은 창문을 이용해 침입하는 것과 같다.

5. **설치(Installation)**

   목표 시스템에 악성코드를 설치하는 단계이다.

   예를 들어 집 안에 몰래 도구를 설치하는 것이다.

6. **명령 및 제어(Command & Control)**

   감염된 시스템을 외부에서 원격으로 조종하는 단계이다.

   예를 들어 밖에서 무전기로 침입자를 조종하는 것과 같다.

7. **행동 개시(Actions on Objectives)**

   정보 탈취 등 최종 목적을 실행하는 단계이다.

   예를 들어 돈을 훔치거나 중요한 물건을 가져가는 것이다.

### 왜 1번이 정답일까?

첫 번째 단계는 공격할 대상을 조사하는 정찰이고, 네 번째 단계는 시스템의 취약점을 이용하는 악용이다.

따라서 ㄱ은 정찰, ㄴ은 악용이 정답이다.

**시험 암기:** 정찰 → 무기화 → 전달 → 악용 → 설치 → 명령&제어 → 행동개시

## 2. SNMP 공격에 해당하지 않는 것

**정답: 4번 (버퍼 오버플로우)**

### 핵심 개념
SNMP(Simple Network Management Protocol)는 네트워크 장비의 상태를 확인하고 관리하는 프로토콜이다.

쉽게 말하면 관리자가 컴퓨터나 공유기 같은 네트워크 장비의 상태를 확인하고 설정을 변경할 수 있도록 도와주는 기능이다.

그런데 접근통제가 제대로 되어 있지 않으면 권한이 없는 사람이 장비에 접근해서 문제를 일으킬 수 있다.

### 보기 설명

1. **장치 구성 변경**

   공격자가 네트워크 장비의 설정을 마음대로 바꿀 수 있다.

2. **라우팅 테이블 조작**

   데이터가 이동하는 경로를 바꿔서 엉뚱한 곳으로 보내게 할 수 있다.

3. **악의적인 TFTP 서버 구동**

   악성 파일을 주고받는 서버를 실행하는 등 악용할 수 있다.

4. **버퍼 오버플로우**

   프로그램이 할당된 메모리 공간보다 많은 데이터를 넣어서 오류를 일으키는 공격이다.

### 왜 4번이 정답일까?

1~3번은 SNMP의 접근통제 미흡으로 발생할 수 있는 장비 관리 및 설정 악용 사례이다.

반면 버퍼 오버플로우는 프로그램의 메모리 처리 취약점을 이용하는 공격이다.

즉, SNMP 접근통제 미흡으로 인한 대표적인 공격 유형과는 다른 개념이기 때문에 4번이 정답이다.

**시험 암기:** SNMP = 네트워크 장비 관리 / 버퍼 오버플로우 = 메모리 취약점 공격

## 3. 윈도우 공유 드라이브(C$) 제거 명령어

**정답: 3번**

### 핵심 개념
윈도우에서는 다른 컴퓨터가 내 컴퓨터의 폴더나 드라이브에 접근할 수 있도록 공유 기능을 제공한다.

여기서 C$는 C 드라이브에 접근할 수 있도록 만들어진 기본 관리 공유이다.

공유를 제거하는 명령어는 다음과 같다.

```bash
net share c$ /delete
```

### 명령어 설명

- `net share`: 공유 폴더를 관리하는 명령어
- `c$`: 공유를 제거할 대상
- `/delete`: 삭제하라는 명령

### 왜 3번이 정답일까?

공유 이름인 `c$` 뒤에 `/delete`를 붙여서 해당 공유를 제거하기 때문이다.

### 함께 기억하기

- 공유 확인: `net share`
- 공유 삭제: `net share 공유이름 /delete`

**시험 암기:** net share + 공유 이름 + /delete

## 4. 리눅스 패스워드 관련 파일의 권한 및 소유주

**정답: 4번**

### 핵심 개념
리눅스에는 사용자 계정과 비밀번호 정보를 관리하는 파일이 있다.

대표적으로 `/etc/passwd`와 `/etc/shadow`가 있다.

여기서 헷갈리기 쉬운 부분은 패스워드 관련 파일이라고 해서 무조건 shadow만 해당하는 것은 아니라는 점이다.

두 파일 모두 패스워드 관련 파일이지만 역할이 다르다.

쉽게 말하면 다음과 같다.

- `/etc/passwd` = 누가 이 컴퓨터를 사용하는지 기록한 명부
- `/etc/shadow` = 사용자들의 비밀번호 정보를 보관하는 금고

### 1) /etc/passwd

사용자 계정 정보를 저장하는 파일이다.

- 사용자 이름
- 사용자 ID
- 그룹 ID
- 홈 디렉터리
- 로그인 셸
- 비밀번호 관련 필드

일반적으로 다음과 같은 권한과 소유주를 가진다.

```bash
-rw-r--r-- 1 root root /etc/passwd
```

- 소유자: root
- 그룹: root
- 권한: 644

일반 사용자도 계정 정보를 읽을 수 있어야 하기 때문에 읽기 권한이 허용되어 있다.

### 2) /etc/shadow

사용자의 비밀번호 해시값과 비밀번호 변경 날짜, 만료 정보 등을 저장하는 파일이다.

일반적으로 다음과 같은 권한과 소유주를 가진다.

```bash
-rw-r----- 1 root shadow /etc/shadow
```

- 소유자: root
- 그룹: shadow
- 권한: 640

비밀번호 정보가 들어 있기 때문에 일반 사용자가 함부로 읽지 못하도록 제한해야 한다.

### 왜 4번이 정답일까?

문제를 처음 보면 패스워드 관련 파일이라고 했기 때문에 비밀번호를 저장하는 `/etc/shadow`가 정답이라고 생각하기 쉽다.

하지만 문제에서 중요한 부분은 어떤 파일이 비밀번호를 저장하느냐가 아니라 각 파일의 권한과 소유주가 올바르게 설정되어 있느냐이다.

`/etc/passwd`도 사용자 계정과 인증에 필요한 정보를 관리하기 때문에 패스워드 관련 파일에 포함된다.

4번은 다음과 같다.

```bash
-rw-r--r-- 1 root root /etc/passwd
```

이는 `/etc/passwd`의 일반적인 권한 및 소유주 설정과 일치한다.

따라서 4번이 정답이다.

### 시험 암기

| 구분 | /etc/passwd | /etc/shadow |
|---|---|---|
| 역할 | 사용자 계정 정보 | 비밀번호 해시 정보 |
| 소유자 | root | root |
| 그룹 | root | shadow |
| 권한 | 644 | 640 |

**가장 중요한 부분**

- passwd = 사용자 계정 정보 / root:root / 644
- shadow = 비밀번호 해시 정보 / root:shadow / 640

passwd와 shadow는 둘 다 패스워드 관련 파일이라는 점을 기억하자.

## 5. DEP(Data Execution Prevention)로 대응하는 공격

**정답: 2번 (Heap Spray 공격)**

### 핵심 개념
DEP는 데이터 영역에서 프로그램 코드가 실행되는 것을 막아주는 보안 기능이다.

컴퓨터 메모리에는 프로그램을 실행하는 영역과 데이터를 저장하는 영역이 있다.

DEP는 데이터를 저장하는 영역에 들어 있는 내용이 프로그램처럼 실행되지 못하도록 막는다.

쉽게 비유하면 다음과 같다.

- 실행 영역 = 요리하는 주방
- 데이터 영역 = 식재료를 보관하는 창고
- DEP = 창고에 있는 식재료를 마음대로 불에 올려 요리하지 못하게 막는 규칙

### 왜 2번이 정답일까?

Heap Spray 공격은 메모리의 힙(Heap) 영역에 공격자가 원하는 데이터를 대량으로 뿌려 놓고 이를 이용해 공격을 성공시키려는 기법이다.

DEP는 데이터 영역의 코드 실행을 막기 때문에 Heap Spray를 이용한 공격을 어렵게 만들 수 있다.

### 다른 보기 설명

1. **XSS 공격**

   웹페이지에 악성 스크립트를 삽입하는 공격이다.

2. **Heap Spray 공격**

   메모리의 힙 영역에 공격에 사용할 데이터를 대량으로 배치하는 공격 기법이다.

3. **SQL Injection 공격**

   SQL 명령어를 삽입해서 데이터베이스를 공격하는 기법이다.

4. **CSRF 공격**

   사용자가 의도하지 않은 요청을 보내도록 만드는 공격이다.

**시험 암기:** DEP = 데이터 영역의 코드 실행 방지 = Heap Spray 대응

## 6. 제로 트러스트(Zero Trust)

**정답: 1번**

### 핵심 개념
제로 트러스트는 아무도 기본적으로 신뢰하지 않고, 접근할 때마다 신원과 권한을 확인하는 보안 방식이다.

기존에는 회사 내부에 들어온 사람은 어느 정도 믿는 방식이었다.

하지만 제로 트러스트는 다르다.

쉽게 예를 들어보자.

회사 건물에 들어왔다고 해서 모든 방에 자유롭게 들어갈 수 있는 것은 아니다.

- 회사 건물에 들어올 때 신원 확인
- 서버에 접근할 때 다시 권한 확인
- 중요한 파일에 접근할 때 또 확인

이런 식으로 계속 확인하는 것이다.

### 왜 1번이 정답일까?

제로 트러스트는 내부 사용자든 외부 사용자든 기본적으로 신뢰하지 않는다.

접근 권한을 부여하기 전에 반드시 신원과 권한을 확인해야 한다.

### 다른 보기 설명

2. **루트킷**

   시스템에 숨어서 공격자의 접근이나 권한을 유지하는 악성 도구이다.

3. **익스플로잇**

   취약점을 이용하는 공격 코드 또는 기법이다.

4. **제로데이**

   아직 보안 패치가 나오지 않았거나 대응되지 않은 취약점과 관련된 공격이다.

**시험 암기:** Zero Trust = 아무도 믿지 않는다. 항상 확인한다.

## 7. PAM control-flag에 해당하지 않는 것

**정답: 4번 (session)**

### 핵심 개념
PAM(Pluggable Authentication Modules)은 리눅스에서 사용자 인증을 관리하는 기능이다.

사용자가 로그인할 때 비밀번호가 맞는지 확인하는 등 인증 과정을 관리한다.

그런데 PAM에는 인증 결과에 따라 어떻게 처리할지 결정하는 제어 플래그가 있다.

### PAM의 대표적인 제어 플래그

| 제어 플래그 | 의미 |
|---|---|
| required | 실패해도 나머지 검사 진행, 최종적으로 실패 처리 |
| requisite | 실패하면 즉시 인증 실패 |
| sufficient | 성공하면 다른 조건에 따라 인증 성공 가능 |
| optional | 선택적인 검사 |

쉽게 비유하면 학교 출입문에서 학생의 신분을 확인한다고 생각하면 된다.

- required: 일단 확인하고 다른 검사도 진행하지만, 실패했다면 최종적으로 통과 불가
- requisite: 확인에 실패하면 바로 입장 불가
- sufficient: 이 검사에서 성공하면 다른 검사 결과에 따라 바로 통과할 수도 있음
- optional: 선택적으로 확인하는 검사

### 왜 4번이 정답일까?

`session`은 PAM의 제어 플래그가 아니다.

PAM에서 사용하는 모듈 종류 중 하나이다.

즉, 제어 플래그와 모듈 종류를 혼동하면 안 된다.

### PAM 모듈 종류

- account
- auth
- password
- session

**시험 암기**

- Control-flag: required, requisite, sufficient, optional
- Module type: account, auth, password, session

특히 session은 제어 플래그가 아니라 모듈 종류라는 것을 기억하자.

## 8. iptables 정책을 파일로 저장하는 명령어

**정답: 2번**

### 핵심 개념
iptables는 리눅스에서 사용하는 방화벽 관리 도구이다.

쉽게 말하면 컴퓨터에 들어오거나 나가는 네트워크 통신을 허용할지 차단할지 정하는 경비원이라고 생각하면 된다.

현재 설정을 파일로 저장하고 싶다면 다음 명령어를 사용한다.

```bash
iptables-save > iptables.conf
```

### 명령어 설명

- `iptables-save`: 현재 방화벽 규칙을 출력하는 명령어
- `>`: 출력 결과를 파일에 저장
- `iptables.conf`: 저장할 파일 이름

### 왜 2번이 정답일까?

현재 설정을 파일로 저장하는 명령어는 `iptables-save`이기 때문이다.

참고로 반대로 저장된 설정을 다시 불러올 때는 다음 명령어를 사용한다.

```bash
iptables-restore < iptables.conf
```

### 시험 암기

- 저장: `iptables-save`
- 복원: `iptables-restore`

## 9. 유닉스/리눅스 시스템 로그파일 설명

**정답: 3번**

### 핵심 개념
리눅스는 사용자의 로그인 기록이나 명령어 사용 기록을 파일로 저장한다.

각 로그 파일이 어떤 정보를 가지고 있는지 알아보자.

### 로그파일 종류

| 파일 | 저장하는 정보 |
|---|---|
| wtmp | 로그인 및 로그아웃 기록 |
| utmp | 현재 로그인한 사용자 정보 |
| btmp | 로그인 실패 기록 |
| lastlog | 사용자별 마지막 로그인 기록 |
| pacct | 사용자가 실행한 명령어와 사용 시간 등의 기록 |

### 왜 3번이 정답일까?

3번에서는 `btmp`가 사용자별 마지막 로그인 시간을 저장한다고 설명했다.

하지만 이 설명은 틀렸다.

`btmp`는 로그인에 실패한 기록을 저장하는 파일이다.

사용자별 마지막 로그인 시간과 접속 주소 등을 저장하는 파일은 `lastlog`이다.

### 쉽게 구분하기

- wtmp = 언제 들어오고 나갔는지
- utmp = 지금 누가 들어와 있는지
- btmp = 누가 로그인에 실패했는지
- lastlog = 마지막으로 언제 로그인했는지
- pacct = 어떤 명령어를 실행했는지

**시험 암기:** btmp = bad login (로그인 실패)

## 10. 교착상태(Deadlock) 해결 방안

**정답: 3번 (교착상태 복구)**

### 핵심 개념
교착상태는 서로 자원을 기다리다가 아무것도 하지 못하는 상태이다.

쉽게 예를 들어보자.

좁은 길에서 자동차 두 대가 마주 보고 있다.

- 자동차 A는 자동차 B가 지나가기를 기다린다.
- 자동차 B도 자동차 A가 지나가기를 기다린다.
- 결국 둘 다 움직이지 못한다.

이런 상황을 교착상태라고 한다.

### 교착상태 해결 방법

| 방법 | 의미 |
|---|---|
| 예방 | 교착상태가 발생할 조건 자체를 없앰 |
| 회피 | 교착상태가 발생하지 않도록 미리 판단하고 자원을 할당 |
| 탐지 | 교착상태가 발생했는지 찾아냄 |
| 복구 | 발생한 교착상태를 해결함 |

### 왜 3번이 정답일까?

문제에서 중요한 부분은 다음과 같다.

- 교착상태 발견 후
- 환형대기를 배제하거나
- 자원을 중단하는 메모리 할당 기법

이미 교착상태가 발생한 다음에 문제를 해결하는 과정이기 때문에 복구(Recovery)가 정답이다.

쉽게 말하면 자동차 두 대가 이미 막혀 있으니 한 대를 뒤로 물려서 길을 비워주는 것이다.

### 시험 암기

- 예방 = 발생 자체를 막음
- 회피 = 미리 계산해서 피함
- 탐지 = 발생했는지 찾음
- 복구 = 발생한 문제를 해결함
