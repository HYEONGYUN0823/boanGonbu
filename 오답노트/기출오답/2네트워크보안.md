# 네트워크 보안 기출문제 오답노트

# 1번. DDoS 공격 대응 절차

**정답: ④ (마 → 다 → 나 → 라 → 가)**

## 1. 핵심 개념

DDoS(Distributed Denial of Service)는 분산 서비스 거부 공격이다.

여러 대의 컴퓨터나 장치를 이용해서 특정 서버에 엄청난 양의 트래픽을 보내는 공격이다.

쉽게 말하면 식당에 손님이 너무 많이 몰려서 정상적인 손님들이 식사를 하지 못하는 상황과 비슷하다.

공격자는 여러 대의 컴퓨터를 이용해 서버에 요청을 계속 보내고, 서버는 요청을 처리하느라 정상적인 사용자의 요청을 처리하지 못하게 된다.

여기서 중요한 점은 DDoS는 여러 곳에서 동시에 공격이 들어온다는 것이다.

## 2. DDoS 공격 대응 순서

문제에서 제시한 대응 절차는 다음과 같다.

1. 모니터링
2. 공격 탐지
3. 초동 조치
4. 상세 분석
5. 차단 조치

문제의 순서대로 정리하면 다음과 같다.

**마 → 다 → 나 → 라 → 가**

### ① 모니터링

평소 서버의 트래픽과 네트워크 상태를 확인한다.

갑자기 트래픽이 증가하거나 평소와 다른 이상 징후가 발생하는지 살펴본다.

예를 들어 평소에는 1초에 100개의 요청이 들어오던 서버에 갑자기 10만 개의 요청이 들어온다면 이상하다고 판단할 수 있다.

### ② 공격 탐지

모니터링 중 발견한 이상 징후가 실제 공격인지 확인한다.

트래픽이 갑자기 증가했다고 무조건 공격은 아니다.

실제로 많은 사용자가 접속한 것일 수도 있기 때문에 공격 여부를 판단해야 한다.

### ③ 초동 조치

공격이 확인되면 피해가 커지지 않도록 초기 대응을 진행한다.

관련 담당자에게 상황을 알리고 긴급 대응 체계를 가동한다.

### ④ 상세 분석

공격이 어떤 방식으로 이루어지는지 분석한다.

- 공격 출발지
- 공격 트래픽의 양
- 공격에 사용된 프로토콜
- 공격 대상 서버
- 공격 유형

이러한 정보를 분석해서 어떤 방식으로 대응할지 결정한다.

### ⑤ 차단 조치

분석한 내용을 바탕으로 공격 트래픽을 차단한다.

방화벽이나 DDoS 대응 장비 등을 이용해 악성 트래픽을 차단하고 정상적인 사용자가 서비스를 이용할 수 있도록 한다.

## 3. 쉽게 이해하기

식당에 손님이 갑자기 몰렸다고 생각해 보자.

1. 평소보다 손님이 많은지 확인한다. (모니터링)
2. 정상적인 손님인지 단체로 몰려온 이상한 손님인지 확인한다. (공격 탐지)
3. 문제가 있다고 판단하면 직원들에게 상황을 알리고 대응한다. (초동 조치)
4. 누가, 어떤 방식으로 식당 운영을 방해하는지 확인한다. (상세 분석)
5. 문제를 일으키는 사람들의 출입을 제한한다. (차단 조치)

이런 순서라고 생각하면 된다.

## 4. 정답인 이유

DDoS 대응은 먼저 평소 네트워크 상태를 확인하고, 이상 징후가 발견되면 공격 여부를 판단해야 한다.

그다음 초동 조치를 진행하고 공격을 상세하게 분석한 뒤 차단 조치를 수행한다.

따라서 **마 → 다 → 나 → 라 → 가** 순서인 ④번이 정답이다.

## 5. 시험 암기

- 모니터링 = 평소 상태 확인
- 공격 탐지 = 실제 공격인지 확인
- 초동 조치 = 초기 대응
- 상세 분석 = 공격 방식과 출발지 등 분석
- 차단 조치 = 악성 트래픽 차단

**시험 포인트: 모니터링 → 공격 탐지 → 초동 조치 → 상세 분석 → 차단 조치**

# 2번. DNS Spoofing 공격

**정답: ③**

## 1. 핵심 개념

DNS(Domain Name System)는 사람이 이해하기 쉬운 도메인 이름을 IP 주소로 변환해 주는 시스템이다.

예를 들어 인터넷 주소창에 `google.com`을 입력하면 컴퓨터는 DNS를 통해 해당 도메인에 연결할 IP 주소를 확인한다.

사람은 도메인 이름을 사용하지만 컴퓨터는 IP 주소를 이용해 통신하기 때문이다.

### DNS Spoofing이란?

DNS Spoofing은 정상적인 DNS 응답인 것처럼 속여서 가짜 IP 주소를 전달하는 공격이다.

예를 들어 사용자가 정상적인 은행 사이트에 접속하려고 했는데 공격자가 가짜 IP 주소를 전달하면 사용자는 가짜 사이트로 접속할 수 있다.

쉽게 말하면 진짜 목적지로 가야 하는데 누군가 잘못된 주소를 알려줘서 가짜 장소로 가게 만드는 것이다.

## 2. DNS Spoofing의 공격 원리

일반적인 DNS 질의 과정은 다음과 같다.

1. 사용자가 도메인 주소를 입력한다.
2. 컴퓨터가 DNS 서버에 IP 주소를 요청한다.
3. DNS 서버가 해당 도메인의 IP 주소를 응답한다.
4. 컴퓨터가 전달받은 IP 주소로 접속한다.

그런데 공격자가 이 과정에 개입해서 가짜 DNS 응답을 전달하면 문제가 발생한다.

사용자는 정상적인 도메인을 입력했지만 실제로는 공격자가 준비한 가짜 사이트에 접속할 수 있다.

## 3. DNS에서 UDP를 사용하는 이유

DNS는 일반적인 질의와 응답 과정에서 UDP를 기본적으로 사용한다.

UDP는 TCP와 달리 통신을 시작하기 전에 연결을 설정하는 과정이 없다.

그래서 비교적 빠르고 간단하게 데이터를 주고받을 수 있다.

### TCP와 UDP 차이

**TCP**

- 통신 전에 연결을 설정한다.
- 데이터가 정상적으로 전달되었는지 확인한다.
- 신뢰성이 높다.
- UDP보다 상대적으로 절차가 많다.

**UDP**

- 연결 설정 과정이 없다.
- 데이터 전달을 보장하지 않는다.
- 빠르고 구조가 간단하다.

DNS는 빠르게 질의하고 응답받는 것이 중요하기 때문에 일반적인 DNS 질의에서 UDP를 사용한다.

다만 DNS가 항상 UDP만 사용하는 것은 아니다.

응답 데이터가 크거나 영역 전송(Zone Transfer)을 수행하는 경우 등에는 TCP도 사용한다.

## 4. 정답인 이유

DNS Spoofing은 DNS 통신 과정에서 공격자가 정상적인 DNS 응답인 것처럼 가짜 정보를 전달하는 공격이다.

DNS의 일반적인 질의 과정에서는 UDP를 사용하며, UDP는 연결 설정 과정이 없는 비연결형 프로토콜이다.

따라서 DNS 통신의 UDP 특성과 인증 및 응답 검증이 충분하지 않은 환경을 악용할 수 있다는 내용이 핵심이다.

정답은 ③번이다.

## 5. 시험 암기

- DNS = 도메인 이름을 IP 주소로 변환
- DNS Spoofing = 가짜 DNS 응답을 전달하는 공격
- DNS 기본 질의 = UDP 53번
- UDP = 비연결형 프로토콜
- TCP = 연결형 프로토콜
- DNS는 상황에 따라 TCP도 사용

**시험 포인트: DNS Spoofing = 가짜 DNS 응답으로 사용자를 잘못된 IP 주소로 유도하는 공격**

# 3번. VoIP 프로토콜

**정답: ③ (SIP)**

## 1. 핵심 개념

VoIP(Voice over Internet Protocol)는 인터넷 프로토콜을 이용해서 음성 통화를 하는 기술이다.

쉽게 말하면 인터넷을 이용한 전화라고 생각하면 된다.

일반적인 전화망 대신 인터넷 네트워크를 이용해서 음성 데이터를 전달한다.

대표적으로 인터넷 전화나 일부 메신저의 음성 통화 기능이 VoIP 기술을 이용한다.

VoIP에서는 통화 연결, 음성 데이터 전송, 통화 품질 관리 등을 위해 여러 프로토콜을 사용한다.

여기서 중요한 프로토콜이 SIP, RTP, RTCP, SDP다.

## 2. 주요 프로토콜 설명

### ① SIP (Session Initiation Protocol)

SIP는 통신 세션을 설정하고 관리하는 프로토콜이다.

쉽게 말하면 전화를 걸고, 상대방이 전화를 받고, 통화를 종료하는 과정을 담당한다.

대표적인 기능은 다음과 같다.

- 통화 연결
- 통화 종료
- 통화 참여자 관리
- 통화 세션 변경

즉, 실제 음성을 전달하는 역할보다는 통화가 시작되고 종료되는 과정을 관리하는 역할이다.

### ② RTP (Real-time Transport Protocol)

RTP는 실시간으로 음성이나 영상 데이터를 전달하는 프로토콜이다.

쉽게 말하면 실제 통화할 때 상대방의 목소리를 전달하는 역할이다.

SIP가 전화를 연결해 주는 역할이라면 RTP는 실제 음성을 전달하는 역할이라고 생각하면 된다.

### ③ RTCP (Real-time Transport Control Protocol)

RTCP는 RTP의 전송 상태와 품질을 관리하는 프로토콜이다.

예를 들어 음성 데이터가 얼마나 잘 전달되고 있는지, 패킷 손실이 발생했는지 등을 확인하는 데 사용된다.

즉, 실제 음성을 전달하는 것이 아니라 음성 데이터의 전송 상태를 관리한다.

### ④ SDP (Session Description Protocol)

SDP는 통신 세션에 필요한 정보를 설명하는 프로토콜이다.

예를 들어 다음과 같은 정보를 전달한다.

- 사용할 미디어 종류
- 사용할 코덱
- 포트 번호
- 전송 방식

쉽게 말하면 통화를 하기 전에 어떤 방식으로 통신할 것인지 알려주는 역할이다.

## 3. 쉽게 이해하기

친구에게 인터넷 전화를 건다고 생각해 보자.

1. SIP: 친구에게 전화를 걸고 통화를 연결한다.
2. SDP: 어떤 코덱과 포트를 사용할지 알려준다.
3. RTP: 실제 친구의 목소리를 전달한다.
4. RTCP: 음성이 얼마나 잘 전달되고 있는지 확인한다.

이렇게 각각 역할이 다르다.

## 4. 정답인 이유

문제에서 물어보는 것은 VoIP에서 세션을 설정하거나 변경하고 해제하는 기능을 담당하는 프로토콜이다.

이러한 역할을 담당하는 프로토콜은 SIP다.

따라서 정답은 ③번이다.

## 5. 시험 암기

- SIP = 통화 연결 및 종료
- RTP = 음성 및 영상 데이터 전송
- RTCP = 전송 품질 및 상태 관리
- SDP = 세션 정보 설명

**시험 포인트: SIP는 통화 세션을 제어하고 RTP는 실제 음성 데이터를 전달한다.**

# 4번. Stateful Inspection 방화벽

**정답: ④**

## 1. 핵심 개념

Stateful Inspection은 상태 기반 패킷 검사 방식이다.

방화벽이 네트워크 패킷을 검사할 때 단순히 IP 주소나 포트 번호만 확인하는 것이 아니라 통신 연결의 상태까지 기억하고 검사하는 방식이다.

여기서 중요한 단어는 State, 즉 상태다.

방화벽이 현재 어떤 통신이 진행 중인지 기억하고 있다는 의미다.

## 2. Stateful Inspection의 동작 원리

예를 들어 내가 웹사이트에 접속한다고 생각해 보자.

1. 내 컴퓨터가 웹 서버에 접속을 요청한다.
2. 방화벽은 해당 연결을 확인한다.
3. 연결이 허용되면 방화벽은 해당 통신의 상태를 기록한다.
4. 웹 서버에서 내 컴퓨터로 응답이 돌아오면 기존 연결에 대한 응답인지 확인한다.
5. 정상적인 응답이라면 통과시킨다.

이때 방화벽은 연결 정보를 저장하는 상태 테이블을 사용한다.

이 테이블에는 통신의 출발지와 목적지, 포트, 프로토콜, 연결 상태 등의 정보가 기록될 수 있다.

## 3. 쉽게 이해하기

식당에 손님이 들어오는 상황을 생각해 보자.

처음 들어온 손님에게 출입을 허용하고 이름을 기록했다고 하자.

잠시 후 그 손님이 화장실에 갔다가 돌아오면 처음 보는 사람처럼 다시 검사하지 않고 이미 입장한 손님이라는 것을 확인할 수 있다.

Stateful Inspection도 이와 비슷하다.

처음 통신을 허용하면 해당 연결의 상태를 기억하고, 이후 돌아오는 응답이 기존 통신에 속하는지 확인한다.

## 4. 다른 방화벽 방식과 비교

### ① ACL (Access Control List)

ACL은 IP 주소, 포트 번호, 프로토콜 등을 기준으로 접근을 허용하거나 차단한다.

예를 들어 다음과 같은 규칙을 만들 수 있다.

- 특정 IP 주소 허용
- 특정 포트 차단
- 특정 프로토콜 허용

ACL은 정해진 조건을 기준으로 패킷을 검사한다.

### ② Application Proxy

Application Proxy는 애플리케이션 계층에서 중간에 위치해 통신을 대신 처리하는 방식이다.

사용자와 서버가 직접 통신하는 것이 아니라 프록시 서버가 중간에서 요청을 받아 전달한다.

### ③ Stateful Inspection

통신 연결의 상태를 기억하고 검사한다.

단순히 개별 패킷만 보는 것이 아니라 기존 연결과 관련된 패킷인지 확인한다.

### ④ DPI (Deep Packet Inspection)

DPI는 패킷의 헤더뿐만 아니라 내부 데이터까지 깊게 분석하는 기술이다.

패킷 안에 어떤 데이터가 들어 있는지 확인해서 악성코드나 특정 애플리케이션의 트래픽 등을 분석할 수 있다.

## 5. 정답인 이유

Stateful Inspection의 핵심은 통신 연결의 상태를 기억하고 검사하는 것이다.

방화벽이 상태 테이블을 이용해서 기존 연결의 정보를 저장하고, 이후 패킷이 해당 연결과 관련된 것인지 확인한다.

따라서 세션 단위로 통신 상태를 관리한다는 설명이 정답이다.

정답은 ④번이다.

## 6. 시험 암기

- Stateful Inspection = 상태 기반 검사
- 연결 상태를 기억한다.
- 상태 테이블을 이용한다.
- 세션 단위로 패킷을 검사한다.
- ACL = IP, 포트, 프로토콜 기준 접근 제어
- Application Proxy = 중간에서 통신을 대신 처리
- DPI = 패킷 내부 데이터까지 분석

**시험 포인트: Stateful Inspection = 연결 상태를 기억하고 검사한다.**

# 5번. SNMP(Simple Network Management Protocol)

**정답: ②**

## 1. 핵심 개념

SNMP(Simple Network Management Protocol)는 네트워크 관리 프로토콜이다.

네트워크에 연결된 장비들의 상태와 정보를 확인하고 관리하기 위해 사용한다.

예를 들어 회사에 여러 대의 서버와 네트워크 장비가 있다고 생각해 보자.

관리자가 모든 장비에 직접 접속해서 상태를 확인하기는 어렵다.

이때 SNMP를 이용하면 관리 시스템에서 네트워크 장비의 상태를 확인할 수 있다.

대표적으로 다음과 같은 정보를 확인할 수 있다.

- 장비의 CPU 사용량
- 메모리 사용량
- 네트워크 트래픽
- 인터페이스 상태
- 장비 작동 상태

## 2. SNMP의 구성 요소

### ① Manager

네트워크 장비를 관리하는 관리 시스템이다.

관리 대상 장비에 정보를 요청하고 응답을 받아 상태를 확인한다.

쉽게 말하면 장비를 관리하는 관리자 역할이다.

### ② Agent

관리 대상 장비에서 실행되는 프로그램이다.

Manager의 요청을 받아 장비 정보를 전달하거나, 장비에서 발생한 이벤트를 Manager에게 알려준다.

쉽게 말하면 관리자의 요청에 응답하는 대상 장비의 담당자라고 생각하면 된다.

### ③ MIB (Management Information Base)

네트워크 장비에서 관리할 수 있는 정보들을 계층적으로 정리한 데이터베이스 구조다.

CPU 사용량, 인터페이스 상태 등 관리할 정보가 어떤 형태로 구성되어 있는지 정의한다.

쉽게 말하면 장비에서 확인할 수 있는 정보들의 목록이라고 생각하면 된다.

## 3. SNMP의 통신 방식

SNMP는 기본적으로 UDP를 사용한다.

여기서 가장 중요한 포트 번호는 161번과 162번이다.

### ① UDP 161번

Manager가 Agent에게 정보를 요청하고, Agent가 응답할 때 사용한다.

즉, 일반적인 SNMP 요청과 응답에 사용되는 포트다.

### ② UDP 162번

Agent가 Manager에게 Trap 메시지를 전달할 때 사용한다.

Trap은 장비에서 특정 이벤트나 문제가 발생했을 때 관리 시스템에 알리는 메시지다.

예를 들어 네트워크 장비의 인터페이스가 갑자기 다운되면 Agent가 Manager에게 Trap을 전달할 수 있다.

## 4. 쉽게 이해하기

회사에 여러 대의 컴퓨터와 네트워크 장비가 있다고 생각해 보자.

- Manager = 장비를 관리하는 관리자
- Agent = 각 장비에서 정보를 전달하는 담당자
- MIB = 장비에서 확인할 수 있는 정보 목록

관리자가 장비의 CPU 사용량을 알고 싶으면 Agent에게 요청한다.

Agent는 해당 정보를 확인해서 Manager에게 전달한다.

그런데 장비에 문제가 발생하면 Agent가 먼저 관리자에게 알려줄 수도 있다.

이때 사용하는 것이 Trap이다.

## 5. 정답인 이유

SNMP는 기본적으로 UDP를 사용하는 네트워크 관리 프로토콜이다.

- UDP 161번 = 요청 및 응답
- UDP 162번 = Trap

따라서 SNMP가 TCP를 사용한다는 설명은 틀린 내용이다.

정답은 ②번이다.

## 6. 시험 암기

- SNMP = 네트워크 장비 관리 프로토콜
- Manager = 관리 시스템
- Agent = 관리 대상 장비의 정보 전달
- MIB = 관리 정보 데이터베이스 구조
- UDP 161 = 요청 및 응답
- UDP 162 = Trap

**시험 포인트: SNMP = UDP 161번, 162번**

# 6번. IPv4 클래스(Class)

**정답: ②**

## 1. 핵심 개념

IPv4 주소는 네트워크에서 장치를 구분하기 위해 사용하는 주소다.

IPv4 주소는 총 32비트로 구성되어 있다.

보통 우리가 보는 형태는 다음과 같다.

`192.168.0.1`

점(.)을 기준으로 4개의 숫자로 나뉘며, 각 숫자는 0부터 255까지의 값을 가질 수 있다.

IPv4 주소는 과거에 네트워크 규모에 따라 A, B, C, D, E 클래스로 구분했다.

## 2. IPv4 클래스별 주소 범위

| 클래스 | 첫 번째 옥텟 범위 | 시작 비트 | 용도 |
|---|---|---|---|
| A | 0 ~ 127 | 0 | 대규모 네트워크 |
| B | 128 ~ 191 | 10 | 중규모 네트워크 |
| C | 192 ~ 223 | 110 | 소규모 네트워크 |
| D | 224 ~ 239 | 1110 | 멀티캐스트 |
| E | 240 ~ 255 | 1111 | 실험 및 연구용 |

※ 실제 사용 가능한 주소에는 별도의 예약 범위가 있다. 위 표는 시험에서 사용하는 클래스별 기본 구분이다.

## 3. 각 클래스 설명

### ① A 클래스

첫 번째 비트가 0으로 시작한다.

주소 범위는 0.0.0.0부터 127.255.255.255까지다.

네트워크 부분이 작고 호스트 부분이 크기 때문에 대규모 네트워크에 사용하도록 설계되었다.

기본 네트워크 부분은 8비트, 호스트 부분은 24비트다.

### ② B 클래스

처음 두 비트가 10으로 시작한다.

주소 범위는 128.0.0.0부터 191.255.255.255까지다.

기본 네트워크 부분은 16비트, 호스트 부분은 16비트다.

### ③ C 클래스

처음 세 비트가 110으로 시작한다.

주소 범위는 192.0.0.0부터 223.255.255.255까지다.

기본 네트워크 부분은 24비트, 호스트 부분은 8비트다.

### ④ D 클래스

처음 네 비트가 1110으로 시작한다.

주소 범위는 224.0.0.0부터 239.255.255.255까지다.

멀티캐스트 용도로 사용한다.

멀티캐스트는 특정 그룹에 속한 여러 장치에게 데이터를 전달하는 방식이다.

### ⑤ E 클래스

처음 네 비트가 1111로 시작한다.

주소 범위는 240.0.0.0부터 255.255.255.255까지다.

실험 및 연구 목적으로 예약된 주소 영역이다.

## 4. 쉽게 이해하기

IPv4 주소를 건물 주소라고 생각하면 된다.

- 네트워크 부분 = 건물 주소
- 호스트 부분 = 건물 안의 방 번호

A 클래스는 건물 수는 적지만 건물 하나에 많은 방을 만들 수 있는 구조다.

C 클래스는 건물 수는 많지만 건물 하나에 들어갈 수 있는 방이 상대적으로 적은 구조다.

즉, 네트워크 부분과 호스트 부분의 크기가 클래스마다 다르다.

## 5. 정답인 이유

문제에서 B 클래스의 주소 범위를 확인해야 한다.

B 클래스는 128.0.0.0부터 191.255.255.255까지다.

시작 비트는 10이다.

보기에서 B 클래스의 범위를 잘못 설명한 항목이 정답이다.

문제의 ④번은 B 클래스의 시작 비트는 맞지만 주소 범위를 191.0.0.0부터라고 제한하고 있기 때문에 틀린 설명이다.

정답은 ②번이다.

## 6. 시험 암기

- A 클래스 = 0으로 시작
- B 클래스 = 10으로 시작
- C 클래스 = 110으로 시작
- D 클래스 = 1110으로 시작
- E 클래스 = 1111로 시작
- A = 0 ~ 127
- B = 128 ~ 191
- C = 192 ~ 223
- D = 224 ~ 239
- E = 240 ~ 255
- D 클래스 = 멀티캐스트

**시험 포인트: B 클래스는 128~191, C 클래스는 192~223**

# 7번. IEEE 802.11 무선 LAN

**정답: ④ (가, 나)**

## 1. 핵심 개념

IEEE 802.11은 무선 LAN(WLAN)을 위한 표준이다.

쉽게 말하면 우리가 사용하는 Wi-Fi와 관련된 무선 네트워크 표준이라고 생각하면 된다.

무선 LAN에서는 AP(Access Point)를 이용하거나 AP 없이 장치끼리 직접 통신할 수 있다.

여기서 중요한 개념은 BSS, ESS, Ad Hoc, Infrastructure, DCF다.

## 2. BSS (Basic Service Set)

BSS는 기본 서비스 집합을 의미한다.

무선 LAN에서 하나의 기본적인 통신 영역을 구성하는 단위다.

AP를 사용하는 경우에는 AP와 그 AP에 연결된 무선 장치들이 하나의 BSS를 구성할 수 있다.

### ① Ad Hoc 방식

AP 없이 무선 장치끼리 직접 통신하는 방식이다.

예를 들어 노트북 두 대가 별도의 AP 없이 직접 연결되어 데이터를 주고받는 상황이다.

### ② Infrastructure 방식

AP를 이용해서 무선 장치들이 통신하는 방식이다.

일반적으로 가정이나 회사에서 사용하는 Wi-Fi가 대표적인 예다.

무선 장치가 AP에 연결되고, AP를 통해 다른 네트워크와 통신한다.

## 3. ESS (Extended Service Set)

ESS는 여러 개의 BSS를 연결해서 하나의 더 넓은 무선 네트워크를 구성하는 것이다.

예를 들어 회사 건물에 층마다 AP가 있다고 생각해 보자.

각 AP는 하나의 BSS를 구성하고, 여러 BSS가 연결되어 더 넓은 네트워크를 형성하면 ESS가 된다.

즉, 여러 BSS를 연결하는 개념이다.

## 4. DS (Distribution System)

DS는 여러 BSS를 연결하는 분배 시스템이다.

쉽게 말하면 여러 AP가 구성하는 BSS들을 서로 연결해 주는 역할이다.

ESS를 구성할 때 BSS 사이의 연결을 지원한다.

## 5. DCF (Distributed Coordination Function)

DCF는 IEEE 802.11 무선 LAN에서 사용하는 매체 접근 방식이다.

기본적으로 CSMA/CA 방식을 사용한다.

### CSMA/CA

Carrier Sense Multiple Access with Collision Avoidance의 약자다.

우리말로는 반송파 감지 다중 접속 및 충돌 회피 방식이다.

쉽게 말하면 데이터를 보내기 전에 다른 장치가 통신하고 있는지 확인하고, 통신 중이면 기다렸다가 전송하는 방식이다.

무선 환경에서는 유선 환경처럼 충돌을 직접 감지하기 어렵기 때문에 충돌을 미리 피하는 방식인 CSMA/CA를 사용한다.

### CSMA/CD와 차이

CSMA/CD는 충돌을 감지하는 방식이다.

주로 과거 공유형 유선 이더넷에서 사용하던 방식이다.

반면 CSMA/CA는 충돌을 피하는 방식이다.

무선 LAN에서는 CSMA/CA를 사용한다.

## 6. 쉽게 이해하기

여러 사람이 한 방에서 대화한다고 생각해 보자.

누군가 말하고 있는데 다른 사람이 동시에 말하면 서로의 말을 알아듣기 어려워진다.

CSMA/CA는 말을 하기 전에 다른 사람이 말하고 있는지 확인하고, 말하고 있다면 잠시 기다렸다가 이야기하는 방식이다.

반대로 CSMA/CD는 동시에 말해서 충돌이 발생했는지 감지하는 방식이라고 생각하면 된다.

## 7. 정답인 이유

문제에서 확인해야 할 내용은 다음과 같다.

- BSS는 기본 서비스 집합이다.
- ESS는 여러 BSS를 연결한 확장 서비스 집합이다.
- DCF는 CSMA/CA 방식을 사용한다.
- 무선 LAN은 CSMA/CD가 아니라 CSMA/CA를 사용한다.

문제의 보기 중 여러 BSS를 연결하는 ESS에 대한 설명과 무선 LAN의 기본적인 접근 방식에 대한 설명이 맞는 항목은 가, 나다.

따라서 정답은 ④번이다.

## 8. 시험 암기

- IEEE 802.11 = 무선 LAN 표준
- BSS = 기본 서비스 집합
- ESS = 여러 BSS 연결
- Ad Hoc = AP 없이 직접 통신
- Infrastructure = AP를 이용한 통신
- DS = BSS를 연결하는 분배 시스템
- DCF = CSMA/CA 사용
- CSMA/CA = 충돌 회피
- CSMA/CD = 충돌 감지

**시험 포인트: 무선 LAN 802.11 = CSMA/CA**

# 8번. Snort 탐지 규칙

**정답: ④**

## 1. 핵심 개념

Snort는 네트워크 침입 탐지 및 방지 시스템에서 사용하는 오픈소스 도구다.

네트워크를 통해 들어오고 나가는 패킷을 분석하고, 미리 설정한 규칙에 해당하는 패킷을 탐지할 수 있다.

Snort는 IDS와 IPS 환경에서 활용된다.

- IDS: 침입 탐지 시스템
- IPS: 침입 방지 시스템

IDS는 공격을 탐지하고 관리자에게 알려주는 역할을 한다.

IPS는 공격을 탐지하는 것뿐만 아니라 실제로 차단하는 역할도 수행한다.

## 2. Snort 규칙의 기본 구조

Snort 규칙은 크게 헤더(Header)와 옵션(Options)으로 구성된다.

기본 구조는 다음과 같다.

`action protocol source_ip source_port -> destination_ip destination_port (options)`

문제에 나온 규칙을 기준으로 살펴보자.

```text
alert tcp any any -> 1.1.1.1 80 (msg:"Example"; content:"example"; dis:100002; rev:1;)
```

※ 문제에 적힌 `aflert`는 `alert`의 오타로 보인다. 또한 `dis`는 `distance`를 의미하는 것으로 보인다.

## 3. 헤더 부분 설명

### ① alert

패킷이 규칙에 일치하면 경고를 발생시킨다는 의미다.

Snort의 규칙에서 어떤 동작을 수행할지 지정한다.

### ② tcp

검사할 프로토콜을 의미한다.

여기서는 TCP 패킷을 검사한다는 뜻이다.

### ③ any any

출발지 IP 주소와 출발지 포트를 의미한다.

첫 번째 any는 출발지 IP 주소가 무엇이든 상관없다는 의미다.

두 번째 any는 출발지 포트가 무엇이든 상관없다는 의미다.

### ④ ->

패킷의 방향을 의미한다.

왼쪽은 출발지, 오른쪽은 목적지다.

### ⑤ 1.1.1.1 80

목적지 IP 주소와 목적지 포트를 의미한다.

즉, 목적지 IP가 1.1.1.1이고 목적지 포트가 80번인 패킷을 검사한다.

## 4. 옵션 부분 설명

괄호 안에는 패킷을 어떤 조건으로 검사할지 지정하는 옵션이 들어간다.

### ① msg

탐지되었을 때 출력할 메시지를 지정한다.

`msg:"Example";`

위 규칙에서는 Example이라는 메시지를 출력한다.

### ② content

패킷 내부에서 특정 문자열이나 데이터를 찾는 옵션이다.

`content:"example";`

패킷의 페이로드에서 example이라는 문자열이 있는지 확인한다.

여기서 페이로드(Payload)는 패킷 안에 실제로 전달되는 데이터 부분이다.

쉽게 말하면 편지 봉투가 아니라 편지 안에 적힌 실제 내용이라고 생각하면 된다.

### ③ distance

이전 content 검색 위치를 기준으로 다음 content를 얼마나 떨어진 곳에서 찾을지 지정하는 옵션이다.

즉, 이전에 찾은 문자열과 다음에 찾을 문자열 사이의 상대적인 거리를 지정한다.

### ④ rev

규칙의 수정 버전을 의미한다.

규칙이 수정되었을 때 버전을 구분하는 데 사용한다.

## 5. 쉽게 이해하기

Snort에게 특정한 조건을 알려주는 것이라고 생각하면 된다.

예를 들어 다음과 같은 규칙이 있다고 하자.

```text
alert tcp any any -> 1.1.1.1 80 (content:"example";)
```

이 규칙은 다음과 같은 의미다.

1. TCP 패킷을 검사한다.
2. 출발지 IP와 포트는 상관없다.
3. 목적지 IP가 1.1.1.1이다.
4. 목적지 포트가 80번이다.
5. 패킷 내부에 example이라는 문자열이 있는지 확인한다.
6. 조건에 일치하면 경고를 발생시킨다.

즉, 특정 서버의 웹 서비스로 향하는 TCP 패킷 중에서 내부에 특정 문자열이 포함된 패킷을 탐지하는 규칙이다.

## 6. 정답인 이유

문제에서 중요한 부분은 `content` 옵션이다.

content는 패킷의 페이로드에서 지정한 문자열이나 데이터를 검색하는 역할을 한다.

따라서 `content:"example"`은 패킷 내부에서 example이라는 문자열을 찾는다는 뜻이다.

정답은 ④번이다.

## 7. 시험 암기

- alert = 경고 발생
- tcp = TCP 프로토콜
- any = 모든 주소 또는 포트
- -> = 패킷 방향
- msg = 탐지 메시지
- content = 패킷 내부 문자열 검색
- distance = 이전 content 위치 기준 상대 거리
- rev = 규칙 수정 버전

**시험 포인트: Snort의 content = 패킷 내부 데이터 검색**

# 9번. NAC(Network Access Control)

**정답: ③**

## 1. 핵심 개념

NAC(Network Access Control)는 네트워크 접근 제어 시스템이다.

네트워크에 접속하려는 사용자의 장치가 보안 정책을 제대로 지키고 있는지 확인하고, 문제가 있으면 네트워크 접근을 제한하는 기술이다.

예를 들어 회사에서 직원이 개인 노트북을 회사 네트워크에 연결하려고 한다고 생각해 보자.

그 노트북에 백신이 설치되어 있는지, 보안 업데이트가 되어 있는지, 회사의 보안 정책을 준수하고 있는지 확인할 수 있다.

문제가 없다면 네트워크 접속을 허용하고, 문제가 있다면 접근을 차단하거나 격리할 수 있다.

## 2. NAC가 확인하는 항목

NAC는 단순히 사용자 계정만 확인하는 것이 아니다.

네트워크에 접속하려는 장치의 보안 상태도 확인할 수 있다.

대표적으로 다음과 같은 항목을 검사한다.

- 백신 프로그램 설치 여부
- 백신 업데이트 상태
- 운영체제 보안 패치 여부
- 보안 정책 준수 여부
- 사용자 인증 여부
- 장치의 접근 권한

## 3. NAC의 동작 과정

일반적인 NAC의 동작 과정은 다음과 같다.

### ① 네트워크 접속 시도

사용자가 컴퓨터나 노트북을 이용해 네트워크에 접속하려고 한다.

### ② 사용자 및 장치 인증

사용자가 정상적인 사용자인지 확인한다.

필요한 경우 인증 서버를 이용해 사용자 계정과 접근 권한을 확인한다.

### ③ 보안 상태 검사

접속하려는 장치에 백신이 설치되어 있는지, 보안 업데이트가 되어 있는지 등을 검사한다.

### ④ 접근 허용 또는 차단

보안 정책을 준수하고 있다면 네트워크 접속을 허용한다.

반대로 문제가 있다면 네트워크 접근을 차단하거나 별도의 격리 네트워크로 이동시킬 수 있다.

### ⑤ 보안 조치

격리된 장치가 백신 업데이트나 보안 패치 등을 완료하면 다시 정상적인 네트워크에 접속할 수 있도록 처리할 수 있다.

## 4. 쉽게 이해하기

학교에 들어갈 때 출입증을 확인하는 상황이라고 생각하면 된다.

학교에 들어오려는 사람이 학생인지 확인하고, 출입 권한이 있는지 검사한다.

그런데 NAC는 여기서 한 단계 더 나아간다.

학생인지 확인하는 것뿐만 아니라, 학교에 들어오려는 노트북이 안전한 상태인지까지 검사하는 것이다.

예를 들어 백신이 설치되어 있지 않거나 보안 업데이트가 되어 있지 않다면 네트워크에 접속하지 못하게 할 수 있다.

## 5. NAC와 관련된 기술

### ① RADIUS

RADIUS는 네트워크 접근 인증과 권한 관리에 사용되는 프로토콜이다.

사용자가 네트워크에 접속할 때 인증 정보를 확인하고 접근 권한을 관리하는 데 활용할 수 있다.

### ② Kerberos

Kerberos는 티켓 기반 인증 프로토콜이다.

사용자의 신원을 확인하고 네트워크 환경에서 안전하게 인증할 수 있도록 도와준다.

### ③ IDS

IDS(Intrusion Detection System)는 침입 탐지 시스템이다.

네트워크나 시스템에서 발생하는 비정상적인 활동과 공격 패턴을 탐지한다.

### ④ IPS

IPS(Intrusion Prevention System)는 침입 방지 시스템이다.

공격을 탐지하는 것뿐만 아니라 실제 공격 트래픽을 차단하는 역할도 한다.

## 6. 정답인 이유

③번은 패킷의 특징이나 공격 패턴을 분석해서 악성 트래픽을 탐지하는 내용이다.

이러한 기능은 NAC보다는 IDS/IPS의 역할에 가깝다.

NAC의 핵심은 네트워크에 접속하려는 장치의 보안 상태와 접근 권한을 확인하는 것이다.

따라서 NAC의 기능과 거리가 먼 ③번이 정답이다.

## 7. 시험 암기

- NAC = 네트워크 접근 제어
- 장치의 보안 상태 확인
- 백신 설치 및 업데이트 확인
- 운영체제 보안 패치 확인
- 보안 정책 위반 시 접근 차단 또는 격리
- RADIUS = 네트워크 접근 인증
- Kerberos = 티켓 기반 인증
- IDS = 침입 탐지
- IPS = 침입 탐지 및 차단

**시험 포인트: NAC = 네트워크에 접속하는 장치의 보안 상태를 확인하고 접근을 제어한다.**

# 시험 직전 암기 노트

## 1. DDoS

모니터링 → 공격 탐지 → 초동 조치 → 상세 분석 → 차단 조치

## 2. DNS

- DNS = 도메인을 IP 주소로 변환
- DNS Spoofing = 가짜 DNS 응답
- DNS 기본 질의 = UDP 53번

## 3. VoIP

- SIP = 통화 연결 및 종료
- RTP = 음성 및 영상 데이터 전송
- RTCP = 전송 품질 관리
- SDP = 세션 정보 기술

## 4. 방화벽

- ACL = IP, 포트 등을 기준으로 접근 제어
- Application Proxy = 중간에서 통신을 대신 처리
- Stateful Inspection = 세션 상태 기억
- DPI = 패킷 내부 데이터까지 분석

## 5. SNMP

- SNMP = 네트워크 장비 관리
- UDP 161 = 요청 및 응답
- UDP 162 = Trap
- Manager = 관리 시스템
- Agent = 관리 대상 장비
- MIB = 관리 정보 구조

## 6. IPv4 클래스

- A = 0 ~ 127
- B = 128 ~ 191
- C = 192 ~ 223
- D = 224 ~ 239
- E = 240 ~ 255

시작 비트:

- A = 0
- B = 10
- C = 110
- D = 1110
- E = 1111

## 7. IEEE 802.11

- 802.11 = 무선 LAN
- BSS = 기본 서비스 집합
- ESS = 여러 BSS 연결
- Ad Hoc = AP 없이 직접 통신
- Infrastructure = AP를 이용한 통신
- DS = BSS를 연결하는 분배 시스템
- DCF = CSMA/CA

## 8. Snort

- alert = 경고 발생
- tcp = TCP 프로토콜
- any = 모든 주소 또는 포트
- msg = 경고 메시지
- content = 패킷 내부 문자열 검색
- distance = 이전 content 기준 상대 거리
- rev = 규칙 버전

## 9. NAC

- NAC = 네트워크 접근 제어
- 백신 및 보안 업데이트 확인
- 보안 정책 위반 장치 차단 또는 격리
- RADIUS = 네트워크 접근 인증
- Kerberos = 티켓 기반 인증
- IDS = 침입 탐지
- IPS = 침입 차단
