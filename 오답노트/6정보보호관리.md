## 1. 위험관리

### ❌ 오답노트: 위험관리 계획 과정 옳지 않은 것
> **정답**: "효과적인 보안에는 자산에 대한 보안 계층이 **단일화**되어 있는 하나의 대책의 조합이 요구된다"

**왜?** 효과적인 보안은 하나의 대책으로 끝나는 게 아니라 **여러 계층을 겹쳐서** 방어하는 "다중 방어(Defense in Depth)"가 핵심이야.

```
인터넷 → 방화벽 → IDS/IPS → WAF → 서버 접근통제 → 백신
```

하나가 뚫려도 다음 계층이 막아주는 구조가 효과적인 거지, "단일화된 하나의 대책"은 틀린 설명이야. (나머지 보기 — 위험관리는 위험분석·위험평가·대책설정 3단계로 구분, 위험분석은 간단한 초기분석부터 시작 가능, 위험평가는 노출된 위협을 평가·식별하는 것 — 는 전부 맞는 설명)

> 🔑 보안 = 단일 대책 ❌ / 여러 계층으로 방어(다중방어) ⭕

### ❌ 오답노트: 잔류위험(Residual Risk) 적절하지 않은 것
> **정답**: "잔류위험이 존재할 경우 이를 **완전히 제거**하기 위하여 상세위험분석을 수행하는 것이 일반적이다"

**왜?** 잔류위험은 보안대책을 적용해도 **남아있을 수밖에 없는 위험**이야. 위험관리의 목적은 위험을 0으로 만드는 게 아니라 **조직이 감당할 수 있는 수준**으로 관리하는 것이기 때문에, 잔류위험은 회피·이전·감소·수용 등으로 "처리"하는 것이지 "완전히 제거"하는 게 목적이 아니야.

```
위험 100 → 보안대책 적용 → 위험 20(잔류위험) → 조직이 수용 가능한 수준인가?
```

> 🔑 잔류위험 = 완전제거 대상 ❌ / 수용 가능한 수준으로 관리 ⭕

### ❌ 오답노트: 위험분석 빈칸 채우기 (위험의 정의 공식)
> **정답**: ㄱ=**취약성**, ㄴ=**위험**, ㄷ=**발생가능성**, ㄹ=**위협**

**핵심 단서**: 지문에 "ㄴ은 잠재적 손실액과 발생확률의 곱"이라고 나와 있는데, 이게 바로 **위험(Risk)의 정의**야.

```
위험 = 잠재적 손실액 × 발생가능성
```

| 용어 | 쉽게 말하면 |
|---|---|
| 자산 | 지켜야 하는 것 |
| **취약성** | 공격받기 쉬운 약점 |
| **위협** | 공격하거나 피해를 줄 수 있는 원인 |
| **위험** | 위협이 취약점을 공격해서 실제 피해가 발생할 가능성과 그 크기 |

> 🔑 흐름: 자산 → 취약성(약점) → 위협(공격원인) → 위험(손실×발생가능성). 이 공식만 기억하면 ㄱㄴㄷㄹ 순서 문제는 거의 다 풀 수 있어.

## 2. BCP & 재해복구시스템

### BCP 접근 5단계 순서
> **정답**: 사업영향평가(BIA) → 복구전략개발 → 복구계획수립

```
프로젝트 범위설정·기획
      ↓
사업영향평가(BIA) — "뭐가 중요한지"
      ↓
복구전략 개발 — "어떻게 살릴지"
      ↓
복구계획 수립 — "구체적으로 어떻게 할지"
      ↓
수행 · 테스트 · 유지보수
```

> 🔑 암기: **BIA → 전략 → 계획** ("중요한 게 뭐지? → 어떻게 살리지? → 구체적으로 어떻게 하지?")

### ⚠️ 오답노트: 재해복구시스템 유형과 RTO (최종 정정!)
> **정답**: **콜드 사이트의 RTO를 "수 일~수 주"라고 한 게 틀림** (실제로는 **수 주~수개월**)

**⚠️ 헷갈리는 이유**: 웜 사이트를 "수 일~수 주"로 설명한 보기는 **맞는 설명**이야. 틀린 건 콜드 사이트 쪽이었어 — 콜드 사이트는 재해 발생 후 장비·시스템을 아예 새로 구축해야 하는 수준이라 복구에 **수 주~수개월**이 걸려.

| 유형 | 준비 상태 | RTO |
|---|---|---|
| 미러 사이트 | 거의 동일하게 실시간 복제 | ⚡ 즉시 |
| 핫 사이트 | 장비·시스템 미리 준비 | 🔥 수시간 이내 |
| **웜 사이트** | 일부만 준비 | 🌤️ **수 일~수 주** |
| **콜드 사이트** | 장소·기본설비만 준비 | 🐢 **수 주~수개월** |

> 🔑 암기: **미러 → 핫 → 웜 → 콜드**, 빠름 → 느림. RTO가 짧을수록 미리 준비된 게 많다는 뜻이야.

## 3. 정보보안제품 평가기준 (CC 계층구조)

### ❌ 오답노트: 보안기능 요구사항 계층구조 틀린 것
> **정답**: 컴포넌트를 "보호프로파일·보안목표명세서에서 선택 가능한 **최대** 단위"라고 한 게 틀림

```
클래스 → 패밀리 → 컴포넌트 → 엘리먼트
(큰 분류)                    (가장 세부적인 단위)
```

| 단위 | 정의 |
|---|---|
| 클래스 | 동일 보안목적을 가지는 패밀리들의 집합 |
| 패밀리 | 동일 목적이나 강도·제약사항이 다른 컴포넌트들의 집합 |
| **컴포넌트** | PP·ST에서 선택 가능한 단위 (최대 단위 아님) |
| 엘리먼트 | 보안기능을 세부적으로 표현하는 **가장 작은** 단위 |

**왜?** 컴포넌트보다 더 세부적인 **엘리먼트**가 존재하기 때문에, 컴포넌트를 "최대 단위"라고 부를 수 없어.

## 4. ISMS-P 인증체계

### ISMS-P 관리체계 수립 및 운영 4단계
> **정답**: 관리체계 기반마련 → 위험관리 → 관리체계 운영 → 관리체계 점검 및 개선

```
① 기반 마련 — "보안관리 틀부터 만들자"
      ↓
② 위험관리 — "뭐가 위험한지 찾자"
      ↓
③ 운영 — "정책·대책을 실제로 적용하자"
      ↓
④ 점검 및 개선 — "제대로 하고 있나 확인하고 고치자"
```

> 🔑 암기: **기 → 위 → 운 → 점**

### '정보보호 정책' 통제 목표가 아닌 것
> **정답**: 정책의 **작성방법**

정보보호 정책의 통제 목표는 **승인 및 공표 / 체계 / 유지관리**야. "어떻게 예쁘게 작성할 것인가" 같은 작성방법론은 통제 목표에 포함되지 않아.

### ❌ 오답노트: 정보시스템 도입 및 개발보안 옳지 않은 것
> **정답**: 개발·시험 시스템이 운영시스템과 분리되어 있으므로 "**절차만 수립되어도 무방하다**"는 설명

**왜?** 개발·시험 환경에서도 운영데이터가 사용될 수 있기 때문에, 절차만 세워놓는 걸로는 부족하고 **실제 보호조치(기술적 통제)**까지 갖춰야 해. (개발·운영 시스템 분리, 통제된 절차를 통한 이관, 외주 개발 시 계약서에 보안요구사항 명시 — 나머지 보기는 전부 맞는 설명)

> 🔑 개발·운영 환경 분리 + 절차 O + **실제 보호조치도 필요** (절차만으론 부족)

### ❌ 오답노트: 주요 직무자 지정 및 관리 틀린 것
> **정답**: "**파견근로자, 시간제근로자 등을 제외한** 임직원 중 업무상 개인정보를 취급하는 자를 개인정보취급자로 지정"

**왜?** 개인정보취급자 지정 기준은 **고용형태가 아니라 실제로 업무상 개인정보를 취급하는지**로 판단해. 파견직·시간제 직원이라도 개인정보를 다룬다면 당연히 개인정보취급자로 지정·관리해야 해.

> 🔑 개인정보취급자 = 고용형태 무관, **실제 취급 여부**로 판단

### ISMS-P 인증심사의 종류가 아닌 것
> **정답**: **보강심사** (실제 종류는 최초심사·사후심사·갱신심사)

> 🔑 암기: **최초 / 사후 / 갱신** ⭕, 보강 ❌

## 5. 법률·제도

### IT서비스 구축단계 사전 보안점검 제도
> **정답**: **정보보호 사전점검 제도**

구축 **단계에서 미리** 취약점을 분석하고 보호대책을 수립하는 컨설팅 활동으로, 투자금액 5억원 이상인 정보통신서비스가 권고 대상이야. (ISMS-P=관리체계 인증, 보안성심의=시스템 보안성 평가, 주요정보통신기반시설 취약점분석평가=기반시설 대상)

### ❌ 오답노트: GDPR 적용 대상이 아닌 것
> **정답**: "EU 주민의 정보와 **무관**하지만 EU의 **생산품**이 포함된 물품·서비스를 제공하는 기업"

**왜?** GDPR의 역외적용 기준은 **EU 주민의 개인정보와 관련이 있는지**가 핵심이야 — EU에 사업장이 있거나, EU 주민에게 물품·서비스를 제공하거나, EU 주민의 행동을 모니터링하는 경우에 적용돼. "EU산 제품을 사용한다"는 것 자체는 GDPR 적용 기준이 아니야.

> 🔑 GDPR 핵심 키워드: **EU 주민에게 서비스 제공 / EU 주민 행동 모니터링 / EU 내 사업장** (EU산 제품 사용 여부 ❌)

### 사이버위기경보 등급 — 복수 ISP망 장애·마비
> **정답**: **경계** 단계

```
관심 → 주의 → 경계 → 심각
(낮음)              (높음)
```

여러 ISP망에 동시에 장애·마비가 발생한 상황은 단순 관심·주의 수준을 넘어서는 **경계** 단계에 해당해.

## 6. 정보보호 조직의 역할과 책임

### ❌ 오답노트: 정보보호 조직 구성원의 역할과 책임 틀린 것
> **정답**: "데이터 관리자는 정보자산에 대한 책임을 보유한 **현업관리자**"라는 설명

**왜?** 정보자산에 대한 최종 책임은 **정보자산 관리자(Owner)**의 역할이야. 데이터 관리자는 데이터 자체를 다루고 관리하는 역할이지, 정보자산에 대한 궁극적 책임(Owner)을 지는 역할과는 구분돼.

| 역할 | 책임 |
|---|---|
| **최고 경영자** | 정보보호 **총괄 책임** |
| 데이터 관리자 | **데이터 관리** (자산에 대한 최종 책임 X) |
| 프로세스 관리자 | 담당 시스템의 보안정책 준수 **보증** |
| 사용자 | 정보보호정책·절차 **준수** |

> 🔑 정보자산에 대한 최종 책임 = **정보자산 관리자(Owner)**, 데이터 관리자 ≠ Owner
