## 1. FTP 보안

### FTP 전송 모드 (Active/Passive)
**정답**: 기본은 **Active 모드**이며, Passive 모드로의 변경은 **FTP 클라이언트**가 결정한다

FTP는 두 개의 연결을 사용해: **제어 연결**(명령 주고받기)과 **데이터 연결**(실제 파일 전송).

| 모드 | 데이터 연결 시작 |
|---|---|
| **Active** (기본값) | 서버가 클라이언트로 연결 |
| **Passive** | 클라이언트가 서버로 연결 (방화벽·NAT 환경에 유리) |

> 🔑 모드 선택 권한은 **클라이언트**에게 있어.

### FTP Passive 모드 포트
**정답**: ㄱ=**21**, ㄴ=**1024**

FTP의 제어 연결은 항상 **TCP 21번**을 쓰고, Passive 모드에서 서버가 데이터 연결을 받을 포트는 보통 **1024 이상**의 동적 포트를 사용해.

### FTP 공격 유형 — 익명 사용자 쓰기권한 악용
**정답**: **Anonymous FTP Attack**

보안 절차 없이 익명 사용자의 접속을 허용하고, 그 익명 사용자에게 쓰기 권한까지 있으면 악성코드 업로드가 가능해져. (FTP Bounce=FTP서버를 경유지로 악용, Buffer Overflow=메모리 공격, Brute Force=ID/PW 무작정 대입)

### FTP 명령어
**정답**: **STOR = 원격지 파일 저장**(업로드)

| 명령어 | 의미 |
|---|---|
| **STOR** | 파일 저장(업로드, Store) |
| RETR | 파일 다운로드 |
| RMD | 디렉터리 **삭제**(Remove) |
| MKD | 디렉터리 **생성**(Make) |
| CWD | 디렉터리 **이동**(Change Working Directory) |
| LIST | 디렉터리 목록 보기 |

## 2. 이메일 보안 — PGP

### ⚠️ 오답노트: PGP의 기능이 아닌 것 (표준 5대 서비스 기준)
> **정답**: **송신자 부인방지**가 PGP의 (별도로 분류되는) 기능이 아니다

**⚠️ 왜 헷갈리는가**: PGP의 전자서명은 인증·무결성과 함께 자연스럽게 부인방지 효과도 주긴 하지만, 시험에서 PGP의 표준 기능으로 분류할 때는 보통 아래 **5가지**를 꼽고, "부인방지"는 별도 항목으로 세지 않아:

| PGP 표준 기능 | 설명 |
|---|---|
| **전자서명(인증)** | 누가 보냈는지 확인, 무결성도 함께 제공 |
| **기밀성** | 메일 내용 암호화 |
| **압축** | 암호화 전에 데이터를 압축 |
| **이메일 호환성** | 바이너리 데이터를 텍스트로 변환(Radix-64) |
| **단편화/재조립** | 메일 크기 제한에 맞춰 큰 메시지를 쪼갰다가 재조립 |

> 🔑 단편화/재조립은 실제 PGP 기능이 맞고(옛날 메일 시스템의 크기 제한 대응), "부인방지"라는 표현이 보기에 있으면 PGP의 표준 5대 기능에는 속하지 않는다는 점을 기억해둬.

### ❌ 오답노트: PGP 설명 중 틀린 것 (기밀성 구현 방식 주의!)
> **정답**: "PGP는 기밀성을 위해 비밀키를 메일 송수신자 간에 **미리 교환**한다"는 설명이 틀림

**왜?** PGP는 매번 **임시 대칭키(세션키)**를 새로 만들어서 메일을 암호화하고, 그 대칭키 자체는 **수신자의 공개키**로 암호화해서 같이 보내. 수신자는 자기 개인키로 대칭키를 복호화한 다음, 그 대칭키로 메일을 복호화하는 거야. **미리 교환**하는 게 아니라 **매번 새로 만들어서 공개키로 감싸 보내는** 방식이야.

> 🔑 PGP 기밀성 = 대칭키로 메일 암호화 + 수신자 공개키로 대칭키 암호화 (하이브리드 방식)

## 3. 이메일 보안 — S/MIME & 이메일 공격

### S/MIME과 관련이 가장 적은 것
**정답**: **IEEE 802**

S/MIME은 이메일 보안 표준(공개키 암호, RSA, IETF RFC 3851 등과 관련)인데, IEEE 802는 이더넷(802.3)·Wi-Fi(802.11) 같은 **네트워크(LAN) 표준**이라 이메일 보안과는 거리가 멀어.

### HTML 기능을 악용하는 이메일 공격
**정답**: **Active Contents 공격**

이메일 클라이언트나 브라우저가 HTML(+JavaScript, ActiveX 등)을 실행할 수 있다는 점을 악용해서, 메일을 열기만 해도 악성 콘텐츠가 실행되도록 만드는 공격이야.

### 메일 서버에 대한 공격 기법
**정답**: **서비스 거부 공격(DoS)**

| 공격 대상 | 예시 |
|---|---|
| 메일 클라이언트(사용자 PC) | Active Contents, 트로이목마, 바이러스 메일 |
| **메일 서버** | **서비스 거부 공격(DoS)** |

### 발신자 IP 추적이 가능한 메일 헤더
**정답**: **Received**

메일이 여러 메일 서버를 거칠 때마다 어디서 어디로 전달됐는지가 기록돼서, 여러 개의 Received 헤더를 역순으로 보면 전달 경로(및 발신 IP)를 추적할 수 있어. (Return-Path=반송주소, Message-ID=메일고유식별자, Reply-To=회신주소)

## 4. SSL/TLS

### ❌ 오답노트: SSL 프로토콜 설명 중 잘못된 것
> **정답**: "**네트워크 계층**에 적용되며 **패킷 단위**로 암호화한다"는 설명

**왜?** SSL/TLS는 **응용계층과 TCP(전송계층) 사이**에서 동작해. IP(네트워크) 계층에서 보안을 제공하는 건 **IPsec**이야.

```
응용계층 (HTTP/FTP/SMTP)
      ↓
   SSL/TLS  ← 여기서 동작
      ↓
    TCP
      ↓
     IP    ← IPsec이 여기서 동작
```

### ❌ 오답노트: 웹메일 SSL 설명 중 틀린 것
> **정답**: "**IP 계층**에서 보안 기능을 수행한다"는 설명

위와 같은 함정이야 — SSL은 IP 계층이 아니라 TCP 위에서 동작해. (참고: "TLS는 SSL v3.0과 동일하다"는 표현은 엄밀히는 정확하지 않지만, TLS 1.0이 SSL 3.0을 기반으로 만들어진 후속 버전이라는 취지로 이해하면 돼)

### ❌ 오답노트: SSL 각 계층 설명 중 잘못된 것
> **정답**: "**레코드 계층**에서 암호화 알고리즘을 **선택**한다"는 설명

**왜?** 암호화 알고리즘 협상·인증·키 생성은 **Handshake 계층**의 역할이야. Record 계층은 그렇게 정해진 방식으로 **실제 데이터를 캡슐화·암호화해서 전송**하는 역할만 해.

| 계층 | 역할 |
|---|---|
| **Handshake** | 암호 알고리즘 협상, 서버 인증, 키 생성 |
| **Record** | 실제 데이터 캡슐화·압축·MAC·암호화 |

### ⚠️ 오답노트: SSL Handshake 순서 (최종 정정!)
> **정답**: ② **4 → 5 → 1 → 2 → 3 → 6**

**⚠️ 순서**: ClientHello(④, 버전·암호설정·랜덤데이터 전송) → ServerHello+인증서(⑤) → 클라이언트가 Premaster Secret을 서버 공개키로 암호화해서 전송(①) → 서버가 Master Secret·세션키 생성(②) → **클라이언트가 먼저** 암호통신 준비완료를 알림(③) → **서버가 이어서** 준비완료를 알림(⑥)

> 🔑 **"클라이언트 완료 → 서버 완료"** 순서가 헷갈리기 쉬운 함정이야. 클라이언트가 먼저 세션키 사용 준비가 됐다고 알리고, 그 다음에 서버가 알리는 순서로 기억해둬.

## 5. 웹서버 보안 & Apache 설정

### ❌ 오답노트: 웹서버 보안 강화 조치 중 부적절한 것
> **정답**: "여러 단계의 방화벽으로 보호되는 **내부망**에 배치"

**왜?** 외부에 공개돼야 하는 웹서버를 내부망 깊숙이 두면 오히려 문제가 생겨. 공개 웹서버는 보통 **DMZ**(내부망과 분리된 완충지역)에 배치해서, 웹서버가 뚫려도 내부망까지 공격이 번지지 않도록 하는 게 표준이야.

> 🔑 외부 공개 웹서버 → **DMZ**에 배치

### Apache 디렉터리 리스팅 방지
**정답**: `Options`에서 **`Indexes`** 삭제

`Indexes` 옵션이 켜져 있으면 기본 문서(index.html 등)가 없는 디렉터리에 접근했을 때 파일 목록이 그대로 노출돼. (FollowSymLinks=심볼릭링크 관련, ServerSignature=서버정보 표시, Combined=로그 포맷)

## 6. XSS 공격 & 웹 방화벽(WAF)

### XSS 공격 절차 순서
**정답**: **b → a → e → d → c**

공격자가 게시판에 XSS 코드를 심어둠(b) → 사용자가 그 글에 접근(a) → 웹서버가 그 글을 사용자에게 전달(e) → 사용자 브라우저에서 XSS 코드 실행(d) → 실행 결과가 공격자에게 전달(c)

> 🔑 "심는다 → 본다 → 전달받는다 → 실행된다 → 결과가 간다" 순서로 외워두면 돼.

### ❌ 오답노트: 웹 방화벽(WAF)의 주요 기능이 아닌 것
> **정답**: **IP 주소와 포트 기반 패킷 탐지 및 차단**

**왜?** 이건 **일반 방화벽**의 영역이야. WAF는 HTTP 공격 패턴 탐지, 파일 업로드 검사, 정보 유출 차단처럼 **웹(응용계층) 공격**을 전문적으로 다뤄.

| | 일반 방화벽 | WAF |
|---|---|---|
| 기준 | IP / Port | HTTP 콘텐츠·패턴 |

## 7. 취약점 관리 & 웹 공격 기법

### 공개된 보안 결함에 부여하는 코드
**정답**: **CVE** (Common Vulnerabilities and Exposures) — 예: `CVE-2021-44228`

(ASCII=문자인코딩, STIX=위협정보공유표준, OWASP=웹보안 프로젝트/조직)

### `|`, `&`, `;`, `` ` `` 필터링이 필요한 공격
**정답**: **운영체제 명령 실행(OS Command Injection)**

이 특수문자들은 OS 명령어를 연결·실행할 때 쓰이는 문자라서, 입력값 검증 없이 시스템 명령으로 전달되면 공격자가 임의 명령을 실행할 수 있어.

### 중요정보·에러정보 노출 공격
**정답**: **정보 누출(Information Disclosure)**

개인정보·계정정보·DB정보·서버 구성정보·개발자 코멘트 등이 에러 메시지 등을 통해 노출되면, 공격자의 2차 공격에 악용될 수 있어.

## 8. DNS 보안

### ❌ 오답노트: DNS 보안 취약점과 거리가 먼 것
> **정답**: **중계 취약점**

DNS의 대표적인 취약점은 **Query 정보 변조**, **Cache 변조**(DNS Cache Poisoning), **서비스 거부(DoS)** 세 가지로 정리돼. "중계 취약점"은 DNS의 대표 취약점 분류에 들어가지 않아.

> 🔑 DNS = "질의(Query) → 캐시(Cache) → 서비스(DoS)" 세 가지로 기억

## 9. 데이터베이스 보안

### DB 키 유형 — 대체키(Alternate Key)
**정답**: **Alternate Key**

여러 개의 **후보키(Candidate Key)** 중 하나를 **기본키(Primary Key)**로 선정하면, 선택되지 않고 남은 나머지 후보키들이 **대체키(Alternate Key)**야. (예: 학번을 기본키로 정했다면 "이름+학과"가 대체키)

| 키 종류 | 의미 |
|---|---|
| Candidate Key | 기본키가 될 수 있는 후보 |
| Primary Key | 후보키 중 실제로 선택한 키 |
| **Alternate Key** | 후보키 중 **선택되지 않고 남은** 키 |
| Foreign Key | 다른 테이블의 키를 참조하는 키 |

### ❌ 오답노트: 구성요소엔 접근 가능하지만 전체 정보엔 권한 없는 문제 (Aggregation vs Inference)
> **정답**: **집합(Aggregation)**

**Aggregation(집합)**: 각각의 조각(구성요소)에는 접근 권한이 있지만, 그걸 다 모으면 원래는 접근 권한이 없던 중요한 정보를 알아낼 수 있는 문제.

**Inference(추론)**와 구분하면:

| | 핵심 |
|---|---|
| **Aggregation(집합)** | 접근 가능한 여러 조각을 **모아서** 원래 권한 없는 정보를 얻음 |
| Inference(추론) | 공개된 정보를 **분석**해서 숨겨진 정보를 유추함 |

문제에서 "구성 요소에는 접근 권한이 있다"는 표현이 나오면 Aggregation 쪽이야.

### ❌ 오답노트: DB 보안 통제 기법 중 성격이 다른 것 (정보흐름통제 vs Aggregation 방지)
> **정답**: "정보가 명시적·암시적으로 **보다 낮은 보호수준의 객체로 이동**하는 것을 검사"

**왜?** 이건 **정보 흐름 통제(Information Flow Control)**에 대한 설명이라 나머지 셋(간접 노출 데이터로 추론 방지, 빅데이터 통계분석에서 발생, 질의·응답 데이터 제한)과 성격이 달라. 나머지 셋은 전부 **Aggregation(집합) 문제를 막기 위한 방법**들이야.

### DB 보안 정책 고려사항
**정답**: **가, 나, 다, 라 모두 맞음**

DB 보안 정책은 ① 최고경영자 승인, ② 전 직원 접근 가능하게 배포, ③ 목적·내용에 대한 교육·홍보, ④ 정기·비정기 검토·갱신 — 이 네 가지가 전부 정책 운영의 정상적인 요건이라 다 맞는 설명이야 (특별한 함정 없음).

## 10. 전자상거래 보안 (SET)

### SET 전자봉투(Electronic Envelope) 구성
**정답**: **비밀키 + B(수신자)의 공개키**

전자봉투는 A가 B에게 대칭키(비밀키)를 안전하게 전달하기 위한 방법이야:
- 실제 **데이터는 비밀키(대칭키)**로 암호화
- 그 **비밀키는 수신자(B)의 공개키**로 다시 암호화

B는 자기 개인키로 비밀키를 복호화한 다음, 그 비밀키로 실제 데이터를 복호화해.

> 🔑 한 줄 암기: **"내용은 비밀키로, 비밀키는 받는 사람 공개키로"**

## 11. 디지털 포렌식

### 포렌식 수행 절차 — 증거물 획득 단계
**정답**: **증거물 획득**

컴퓨터 시스템 정보 기록, 원본 매체의 디지털 사진 촬영, 증거 라벨 부착 — 이건 전부 증거를 확보하면서 **원본 상태를 보존·식별**하는 행동이라 "증거물 획득" 단계에 해당해.

| 단계 | 내용 |
|---|---|
| 수사 준비 | 수사 범위·계획 수립, 장비 준비 |
| **증거물 획득** | 원본 보존, 사진 촬영, 라벨 부착, 시스템 정보 기록 |
| 분석 및 조사 | 이미지 복제본으로 실제 파일·로그 분석 |
| 보고서 작성 | 조사 결과 정리 |
