## 1. OSI 계층 & 데이터링크 계층

### ❌ 오답노트: 이더넷 MAC 주소 형식
> **정답**: ③ `07:01:02:01:2C:4B`

MAC 주소는 **16진수 6묶음(48비트)**으로 구성돼: `XX:XX:XX:XX:XX:XX`. ①은 5묶음, ②는 7묶음이라 탈락, ③이 정확히 6묶음이라 정답.

> 🔑 MAC 주소 = 48비트 = 6바이트 = 16진수 6묶음

### ❌ 오답노트: 데이터링크 계층과 관련성 적은 것
> **정답**: ③ (데이터 압축 및 암호화)

데이터링크 계층은 "바로 옆 장치끼리 프레임을 안전하게 전달하는 계층"이야. 오류제어·흐름제어·MAC·멀티포인트 회선제어(CSMA/CD 등)는 전부 여기 속하지만, **압축·암호화는 표현(Presentation) 계층**의 역할이라 가장 관련이 적어.

### ❌ 오답노트: 데이터링크 계층 기능 옳지 않은 것
> **정답**: ④ (Flag 패턴이 데이터 안에 나타나면 **네트워크 계층**에서 처리한다)

**왜?** Flag 패턴이 우연히 데이터 안에 들어있으면 "프레임이 끝났다"고 착각할 수 있어. 이걸 막는 게 **Bit Stuffing**인데, 이 작업은 **데이터링크 계층**(HDLC 등)에서 처리하지 네트워크(IP) 계층과는 전혀 관계없어.

**Flag / Bit Stuffing / CSMA-CD / CSMA-CA 쉽게 이해하기**

| 개념 | 쉬운 설명 |
|---|---|
| **Flag** | 프레임의 "시작·끝 표시" — 편지 봉투에 "여기부터 시작", "여기서 끝"이라고 붙여두는 것 |
| **Bit Stuffing** | Flag와 똑같은 패턴이 데이터 안에 우연히 있으면 착각하지 않도록 비트를 하나 끼워넣는 기법 |
| **CSMA/CD** | 유선랜에서 일단 보내보고, 충돌 나면 감지해서 다시 보내는 방식 ("복도에서 말하다 부딪히면 다시 말함") |
| **CSMA/CA** | 무선랜(Wi-Fi)에서 충돌 나기 전에 미리 조심해서 피하는 방식 ("먼저 눈치 보고 조용할 때 말함") |

> 🔑 **CD는 충돌을 "탐지"하고, CA는 충돌을 "회피"한다.**

## 2. IP 주소 & 서브넷 & ICMP

### ❌ 오답노트: CIDR /27의 서브넷 마스크
> **정답**: ③ 255.255.255.224

`/27`은 앞에서부터 27비트가 1이라는 뜻이야. 8비트씩 끊으면 `11111111.11111111.11111111.11100000` → `255.255.255.224`.

| 표기 | 서브넷마스크 |
|---|---|
| /24 | 255.255.255.0 |
| /25 | 255.255.255.128 |
| /26 | 255.255.255.192 |
| **/27** | **255.255.255.224** ⭐ |
| /28 | 255.255.255.240 |

### 혼잡 시 통보하는 ICMP 메시지
**정답**: ① Source Quench — 네트워크가 혼잡해서 패킷이 버려질 때 "잠깐, 너무 많이 보내!"라고 송신자에게 알려주는 메시지.

| 메시지 | 의미 |
|---|---|
| **Source Quench** | 너무 많이 보내지 마 (혼잡 알림) |
| Destination Unreachable | 목적지 못 감 |
| Time Exceeded | TTL 끝 (Traceroute에서 활용) |
| Parameter Problem | 헤더 오류 |

### ❌ 오답노트: TCP/IP 설명 옳지 않은 것
> **정답**: ③ (애니캐스트는 "일부 수신자들"과 통신한다)

**왜?** 애니캐스트(Anycast)는 여러 후보 중 **가장 가까운 딱 한 명**에게 보내는 방식이야. "일부 수신자"라는 표현이 나오면 틀린 보기일 가능성이 높아.

| 방식 | 대상 |
|---|---|
| Unicast | 한 명 (지정) |
| Broadcast | 전원 |
| Multicast | 그룹 |
| **Anycast** | **가장 가까운 한 명** (후보 중 선택) |

## 3. NAT · PAT · Socket

### Socket 구성
**정답**: Socket = **IP + Port** (MAC 주소는 포함 안 됨)

### ❌ 오답노트: NAT/PAT 설명 틀린 것 (Well-known Port 함정)
> **정답**: PAT은 **Well-known Port(0~1023)를 변환한다는 설명이 틀림**

**왜 헷갈리는가?** Well-known Port는 80(HTTP), 443(HTTPS), 21(FTP)처럼 **이미 정해진 서비스용 포트**야. PAT이 바꾸는 건 이게 아니라, 보통 **내부 PC의 출발지(Source) 포트**야.

**비유로 정리** — 회사 건물이라고 생각해보면:
- **Static NAT** = 사원마다 개인 사무실 1개씩 고정 배정 (1:1, IP 절약 안 됨)
- **Dynamic NAT** = 빈 회의실을 필요할 때 빌려 씀 (IP풀에서 하나 빌림)
- **PAT** = 큰 회의실 1개를 여러 사람이 번호표로 나눠 씀 — **그 번호표가 바로 포트 번호**

예를 들어 PC1(`192.168.0.2:5000`)과 PC2(`192.168.0.3:5000`)가 동시에 인터넷에 접속하면, 공인 IP는 `1.1.1.1` 하나뿐이지만 포트를 각각 `30001`, `30002`로 다르게 배정해서 누가 누구인지 구별해. 이게 "출발지 포트를 바꾸는 것"이지 "Well-known Port를 바꾸는 것"이 아니야.

| 방식 | 특징 |
|---|---|
| Static NAT | 1:1 고정, IP 절약 안 됨 |
| Dynamic NAT | 공인 IP 풀에서 동적으로 빌림 |
| **PAT** | 공인 IP 1개 + **출발지 포트**로 여러 대 구분 ⭐ |

> 💡 참고로 NAT/PAT 자체가 "전혀" 보안 효과가 없는 건 아니야 — 사설 IP를 외부에 직접 노출하지 않는다는 점에서 부수적인 보안 이점은 있어. 다만 NAT가 "보안 기술 자체"는 아니라는 점은 기억해둬. (11번 섹션에서 이어서 다룰게.)

## 4. TCP 흐름제어 & 혼잡제어

### ❌ 오답노트: 혼잡윈도우가 기하급수적으로 증가하는 알고리즘
> **정답**: ③ 느린 시작(Slow Start)

**⚠️ 이름의 함정**: "느린 시작"이라는 이름과 달리, 실제로는 **1→2→4→8→16**처럼 **2배씩 빠르게** 증가해. 임계치(ssthresh)를 넘으면 그때부터 **혼잡회피(Congestion Avoidance)**로 전환되어 1씩만 증가해.

> 💡 고속도로 비유: 차가 없을 땐 속도를 10→20→40→80처럼 확 올리다가(느린시작), 차가 많아지면 80→81→82처럼 조금씩만 올리는(혼잡회피) 것과 같아.

## 5. 라우팅

### ❌ 오답노트: 다익스트라 알고리즘 관련 틀린 것
> **정답**: ② (거리벡터 알고리즘이다)

**왜?** 다익스트라는 **링크상태(Link State)** 알고리즘이야. 거리벡터가 아니야.

| 알고리즘 | 방식 | 대표 프로토콜 |
|---|---|---|
| **거리벡터** | 옆 라우터에게 길을 물어봄 | RIP |
| **링크상태** | 전체 지도를 직접 만들고 다익스트라로 최단경로 계산 | **OSPF** ⭐ |

### 텔넷 로그인 계정 설정
**정답**: `username X password Y`(전역설정모드) → `line vty 0 4` → `login local` 순서

username은 반드시 `Router(config)#`에서 입력해야 하고, 인터페이스 모드(`config-if`)에서는 계정을 만들 수 없어.

### Default Route 설정 이유
**정답**: 라우팅 테이블에 **정보가 없는 목적지**를 위한 것 ("모르면 여기로 보내")

### ❌ 오답노트: 라우터 보안설정 (Blackhole vs uRPF 주의!)
> **정답**: ③ 가, 나, 라

- **가. Egress 필터링**: 내부→외부로 **나가는** 패킷 검사 ✅
- **나. Ingress 필터링**: 외부→내부로 **들어오는** 패킷 검사(ACL 활용) ✅
- **다. (틀림)**: "인터페이스로 들어오는 패킷을 라우팅 테이블로 확인"이라는 설명은 **Blackhole이 아니라 uRPF**에 대한 설명이야. Blackhole은 그냥 특정 트래픽을 쓰레기통처럼 **버리는(폐기하는)** 기법이야.
- **라. uRPF**: 라우팅 테이블을 이용해 출발지 IP가 실제로 그 인터페이스로 들어올 수 있는지 확인해서 위조 패킷을 걸러냄 ✅

| 용어 | 쉽게 기억하기 |
|---|---|
| Egress | 안→밖 나가는 패킷 검사 |
| Ingress | 밖→안 들어오는 패킷 검사 |
| Blackhole | 특정 트래픽을 그냥 버림 |
| **uRPF** | 출발지 IP가 실제 경로와 맞는지 확인 (위조 탐지) |

## 6. NIC & VLAN

### ⚠️ 오답노트: NIC 설명 옳지 않은 것 (표현 주의!)
> **정답**: ④ (네트워크로 전송하기 위해 **병렬**구조로 데이터를 바꾼다)

**⚠️ 왜 헷갈리는가**: 컴퓨터 내부에서는 데이터를 여러 비트씩 한꺼번에(**병렬**) 처리하지만, 랜선으로 나갈 땐 한 줄로 순서대로(**직렬**) 보내야 해. 그래서 NIC는 **병렬→직렬** 변환을 하는 거지, "병렬구조로 바꾼다"는 설명은 방향이 반대라서 틀렸어.

> 🔑 **컴퓨터는 병렬, 네트워크는 직렬** — 이 한 줄만 기억하면 돼. (참고로 "데이터 압축"도 NIC의 일반적인 기능은 아니야 — 그건 표현 계층의 역할이니, 문제에 압축 관련 보기가 나와도 의심해볼 것.)

### ❌ 오답노트: VLAN 설명 잘못된 것
> **정답**: ④ (프로토콜기반 VLAN은 네트워크 주소별로 구성한다)

**왜?** "네트워크 주소(IP 대역)"를 기준으로 나누는 건 **IP 서브넷 기반 VLAN**이야. **프로토콜기반 VLAN**은 IPv4/IPv6/IPX처럼 **어떤 프로토콜을 쓰는지**를 기준으로 나누는 거야.

| VLAN 종류 | 기준 |
|---|---|
| 포트 기반 | 스위치 포트 번호 |
| MAC 기반 | MAC 주소 |
| **프로토콜 기반** | **프로토콜 종류**(IPv4, IPv6, IPX 등) |
| IP 서브넷 기반 | IP 주소 대역(네트워크 주소) |

## 7. 무선보안 & 인증 기술

### 장비 인증 (사용자 아닌 장비를 확인)
**정답**: ② MAC 주소 기반 인증 기술 — "누구인가"가 아니라 "어떤 장비인가"를 확인할 땐 MAC 주소를 등록해서 허가된 장비만 접속시켜.

### 순방향 기밀성(Forward Secrecy)
**정답**: ③ — 현재 세션키·마스터키가 노출돼도 **과거에 암호화된 트래픽**은 영향받지 않음

> 💡 지금 키가 털려도, 작년 대화 내용까지 거슬러 복호화할 수는 없다는 뜻이야.

### ❌ 오답노트: Android 데이터 처리 틀린 것
> **정답**: ④ (민감한 정보 파일을 SD카드 등 외부 저장소에 둔다)

외부 저장소는 다른 앱·사용자가 접근할 수 있어서 위험해. 민감정보는 앱 내부의 보호된 저장공간에 둬야 해.

### ⚠️ 오답노트: OAuth ("인증"이라는 단어에 낚이지 말 것!)
> **문제**: 인터넷 애플리케이션에서 **사용자 인증**에 사용되는 공개 API, 다른 앱이 SNS 사용자 정보에 접근하게 함, **2010년 IETF RFC 5849**
> **정답**: ② OAuth (④ OIDC 아님!)

**⚠️ 왜 헷갈리는가**: 지문에 "사용자 인증"이라는 단어가 나와서 OIDC를 떠올리기 쉬워. 하지만 결정적 단서는 **RFC 5849**야 — 이게 바로 **OAuth 1.0**의 표준 문서 번호거든. OAuth의 본래 핵심은 인증(Authentication)이 아니라 **권한 위임(Authorization)**이야.

| | OAuth | OIDC |
|---|---|---|
| 핵심 | **권한 위임** | **사용자 인증** |
| 질문 | "이 앱이 내 정보 써도 돼?" | "너 누구야?" |
| 기반 | OAuth 1.0/2.0 | OAuth 2.0 위에 구축 |

> 🔑 지문 앞부분("사용자 인증")보다 **RFC 5849라는 구체적 단서**가 훨씬 강력해 — 표준 문서번호·연도가 나오면 그게 결정적 힌트인 경우가 많아.

### 인증 프로토콜에 해당하지 않는 것
**정답**: ② PGP

RADIUS, Kerberos, TACACS는 전부 "너 누구야?"를 확인하는 **인증 프로토콜**이지만, PGP는 **이메일을 암호화하고 전자서명**하는 기술이라 인증 프로토콜로 분류되지 않아.

| 기술 | 분류 |
|---|---|
| RADIUS | 인증 (사용자) |
| Kerberos | 인증 (티켓 기반) |
| TACACS | 인증 (네트워크 장비) |
| **PGP** | **메일 암호화·전자서명** (인증 프로토콜 X) |

## 8. 네트워크 명령어

### ❌ 오답노트: 네트워크 명령어 설명 잘못된 것
> **정답**: ② (ping은 **IDP**를 이용한다)

**왜?** ping은 IDP가 아니라 **ICMP**(Echo Request/Reply)를 사용해.

| 명령어 | 역할 |
|---|---|
| ifconfig | NIC 정보 확인(IP·MAC·서브넷) |
| **ping** | **ICMP**로 연결 확인 |
| nslookup | DNS 조회 |
| tcpdump | 패킷 캡처·분석 |

### ❌ 오답노트: traceroute 설명 옳지 않은 것
> **정답**: ③ (컴퓨터 자신의 내부 네트워크 상태를 보여준다)

**왜?** 그건 ifconfig/netstat의 역할이야. traceroute는 **목적지까지 거쳐가는 경로**를 보여주는 명령어야. (`*`가 나오면 방화벽 등이 UDP를 차단했을 가능성)

### DNS 프로토콜을 사용하지 않는 명령어
**정답**: ③ ifconfig (bind=DNS서버프로그램, dig·nslookup=DNS조회 명령어라 전부 DNS 관련, ifconfig만 무관)

## 9. DoS/DDoS 공격 총정리

### DoS 공격의 특징
**정답**: 가, 나, 라 (다는 틀림 — "추적하기 쉽다"가 아니라 **추적하기 어렵다**)

DoS는 루트 권한 획득이 목적이 아니고, 데이터 변조·탈취 목적도 아니며(가용성 공격), 공격 방법이 매우 다양해. 다만 (특히 DDoS는 좀비 PC를 거치므로) **추적은 오히려 어려워**.

### ❌ 오답노트: Smurf 공격 특징이 아닌 것
> **정답**: ④ (IP 위조해서 SYN 패킷을 대량 전송 — 이건 **SYN Flood** 설명)

Smurf는 **IP Spoofing + ICMP + 브로드캐스트**를 이용해. IP를 피해자로 위장해서 ICMP Echo Request를 브로드캐스트로 뿌리면, 네트워크의 모든 PC가 피해자에게 동시에 응답을 보내서 트래픽이 폭주해.

### TCP SYN Flooding과 관련 없는 것
**정답**: ④ Teardrop (이건 **Fragmentation 공격**이라 TCP SYN과 무관)

SYN Flood는 **Half Open Connection**을 만드는 공격이고, 분산으로 하면 DDoS, 반사 서버를 이용하면 Reflector 공격과도 연관될 수 있어.

### ICMP를 이용하는 DoS 공격 짝지은 것
**정답**: ① Smurf - Ping of Death (둘 다 ICMP 계열. SYN Flood=TCP, UDP Flood=UDP)

### Fragment Overlap 공격
**정답**: 두 번째 fragment의 offset을 조작해서 재조합 시 **첫 번째 fragment 일부를 덮어쓰는** 공격

> 💡 **Tiny Fragment** = 아주 작게 쪼개서 필터링 우회 / **Fragment Overlap** = 겹치게 만들어서 내용을 바꿔치기

### ⚠️ 오답노트: DDoS 공격 유형 나열 (도구 vs 기법 구분!)
> **정답**: ④ **Trinoo, TFN, TFN2K**

**⚠️ 헷갈리는 이유**: Stacheldraht·Smurf·TFN을 묶은 보기도 그럴듯해 보이지만, 이 문제가 묻는 건 **"대표적인 DDoS 공격 도구"**야. Smurf는 DDoS에 이용될 수 있는 **공격 기법**이지, Trinoo/TFN/TFN2K/Stacheldraht 같은 **전용 DDoS 도구(프로그램)** 목록과는 구분해야 해.

| 구분 | 목록 |
|---|---|
| **DDoS 전용 도구** | Trinoo, TFN, TFN2K, Stacheldraht |
| DDoS에 활용 가능한 공격기법 | Smurf, UDP Flooding, SYN Flooding |

### 네트워크 구성 파악(정찰)과 거리가 먼 것
**정답**: ① Smurf 공격 (이건 정찰이 아니라 실제 **서비스 마비 공격**)

Ping Sweep(살아있는 호스트 확인), Traceroute(경로 파악), DNS 정보 획득은 전부 공격 전 **정찰(Reconnaissance)** 단계에 해당해.

### 포트 스캔 (SYN→SYN+ACK받고→RST)
**정답**: ② TCP Half Open Scan — ACK를 안 보내고 RST로 끊어서 "완전한 연결"을 만들지 않아.

### UDP Flooding 시 없는 포트에서 발생하는 패킷
**정답**: ① ICMP Unreachable — 서비스가 없는 포트로 UDP가 오면 "여기 아무것도 없어"라고 ICMP Destination Unreachable로 알려줘.

### ❌ 오답노트: 세션 하이재킹 설명 중 가장 옳지 않은 것
> **정답**: ④ (가짜 DNS 응답을 보내 잘못된 IP로 유도 — 이건 **DNS Spoofing**)

세션 하이재킹은 **이미 만들어진 세션을 훔치는** 공격이고(RST+시퀀스번호 조작 등으로), DNS Spoofing은 **가짜 DNS 응답**으로 엉뚱한 곳으로 유도하는 별개의 공격이야.

### ACK Storm·비동기화 등으로 탐지하는 공격
**정답**: ② TCP 세션 하이재킹 — 공격자가 세션에 끼어들면 양쪽의 TCP 상태가 어긋나(비동기화), ACK가 폭증하는(ACK Storm) 현상이 나타나.

## 10. 침입탐지시스템(IDS) & 보안관제

### ❌ 오답노트: H-IDS보다 N-IDS가 유리하지 않은 것
> **정답**: ① 트로이목마 설치 시도 탐지

트로이목마 설치는 **컴퓨터 내부**(파일 생성·변경, 프로그램 설치)에서 일어나는 일이라 **H-IDS**가 유리해. DDoS·스캐닝·SYN Flood처럼 **네트워크를 오가는** 공격은 N-IDS가 유리하고.

> 🔑 **H-IDS = 컴퓨터 내부 감시 / N-IDS = 네트워크 감시**

### ❌ 오답노트: 지식기반 침입탐지 방법이 아닌 것
> **정답**: ① 통계적 분석

시그니처 분석·페트리넷·상태전이분석은 **이미 알려진 공격 패턴**을 미리 규칙으로 갖고 찾아내는 **지식기반** 탐지야. 통계적 분석은 "평소보다 트래픽이 갑자기 많다"처럼 **정상에서 벗어난 정도**를 보는 **행위(이상)기반** 탐지라서 지식기반이 아니야.

### 금융보안 데이터 통제
**정답**: ④ 비정상 데이터 유입의 통제 — "사전에 정해지지 않은 비정상 데이터 유입 시 예외처리"를 그대로 설명하는 항목.

### ❌ 오답노트: EDR 주요 기능이 아닌 것
> **정답**: ③ 보안사고 확산 영역

EDR(Endpoint Detection and Response)은 **탐지 → 통제(차단) → 치료(복구)**를 담당해. "확산"은 공격자의 행위지 EDR의 기능 영역이 아니야.

## 11. 방화벽 · NAT 심화 · DPI

### ❌ 오답노트: 침입차단시스템 구성과 거리가 먼 것
> **정답**: ③ (자체 공격 대응 기능 + RPC, SNMP 등 관리 서비스 제공)

모든 트래픽이 통과해야 하고, 허가된 트래픽만 통과시키며, 로그로 추적 가능해야 하는 건 맞지만, **RPC·SNMP 같은 관리 서비스를 제공해야 한다**는 건 필수 조건이 아니야 — 오히려 불필요한 서비스는 공격 표면만 늘려.

### N-IPS가 차단하기 가장 어려운 것
**정답**: ③ 악성코드를 포함하는 파일

IP 대역·TCP 포트는 **패킷 헤더**만 보면 되지만, 악성코드 포함 파일은 **내용(payload)까지** 분석해야 해서 대규모 트래픽에서는 처리 부담이 훨씬 커.

### ❌ 오답노트: NAT 설명 옳지 않은 것
> **정답**: ① (NAT의 IP·Port 변경으로는 전혀 보안효과를 가져올 수 없다)

**왜?** NAT가 "보안 기술 자체"는 아니지만, 사설 IP를 외부에 직접 노출하지 않는다는 점에서 **일부 보안상 이점**은 있어. "전혀 없다"는 단정이 틀린 거야.

### ⚠️ 오답노트: 방화벽 ACL 필터링 결과 (순서 검사가 핵심!)
> **규칙**: ①`211.1.99.0/24→32.15.0.0/16 DROP` ②`211.1.0.0/8→32.15.6.0/24 ACCEPT` ③`any→any DROP`
> **정답**: ② 틀림 — 출발지 `211.1.99.1` / 목적지 `32.15.6.15`는 "규칙 2에 의해 허용된다"고 했지만 실제로는 **규칙 1에 걸려서 DROP**된다

**⚠️ 핵심 함정**: `211.1.99.1`은 규칙1의 출발지 대역(`211.1.99.0/24`)에도 해당되고, `32.15.6.15`도 규칙1의 목적지 대역(`32.15.0.0/16`)에 포함돼. 방화벽은 **위에서부터 순서대로 검사해서 처음 걸린 규칙을 적용**하기 때문에, 규칙 2까지 갈 필요도 없이 **규칙 1에서 이미 DROP**되는 거야.

> 🔑 **ACL은 위에서부터 검사 → 처음 매칭되는 규칙 적용 → 그 뒤 규칙은 보지 않는다.** 두 규칙에 동시에 해당해도 항상 먼저 나온 규칙이 이겨.

### DPI (Deep Packet Inspection)
**정답**: ③ DPI — 패킷의 **payload(내용물)**까지 검사해서 애플리케이션 식별, 트래픽 관리, 유해 콘텐츠 차단 등에 활용돼.

## 12. VPN & NAC

### 2계층과 3계층을 모두 지원하는 VPN 프로토콜
**정답**: ③ MPLS

| 프로토콜 | 계층 |
|---|---|
| PPTP | 2계층 |
| L2F | 2계층 (이름에 L2) |
| **MPLS** | **2+3계층** ⭐ |
| IPSec | 3계층 |

### 2계층 + IKE + ESP를 사용하는 VPN
**정답**: ② L2TP

L2TP 자체는 터널만 만들고 보안 기능이 부족해서, 보통 **IPsec과 결합(L2TP/IPsec)**해서 써. IPsec에서 **IKE**(키 교환)와 **ESP**(암호화·인증)를 담당해.

### NAC / NMS / ESM / UTM 구분
**정답**: ① NAC (Network Access Control)

엔드포인트(단말)의 보안 상태(사용자 인증, 백신, 패치, 무결성)를 점검해서 네트워크 접근을 허용·차단하는 시스템이야. Agent 기반(단말에 프로그램 설치, 상태점검에 강함) vs Agentless(네트워크에서 중앙집중 감시, 트래픽 관리에 강함)로 나뉘어.

| 시스템 | 핵심 |
|---|---|
| **NAC** | 단말 상태 점검 후 네트워크 접근 통제 |
| NMS | 네트워크 장비(라우터·스위치) 관리 |
| ESM | 여러 보안장비 로그를 모아 통합 관제 |
| UTM | 여러 보안기능(방화벽+IDS/IPS+VPN 등)을 한 장비에 통합 |

> 🔑 NAC = "너 안전해? 안전하면 들어와"
